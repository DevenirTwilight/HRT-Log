## 替换合同

1. 已有解密、32MiB/100000行预算、类型和白名单校验保留。
2. 仅使用目标库可信当前表与索引 DDL 建立 name=null 的临时内存 SQLite，启用 FK；完整预演插入、旧版兼容、账本缓存重建和现有业务校验。输入绝不能提供 SQL；不会创建解密数据库文件。真正目标继续为 SQLCipher。
3. 输入账本迭代拓扑校验并按父节点先插入，不靠输入 JSON 行序；缺失父节点、循环、重复 ID 先拒绝。预演中的 REVERSE 仍必须引用 CONSUME，绝不因图算法支持 DAG 而允许业务非法链。
4. 在原目标事务内，先捕获全部可信非附件触发器，再移除。附件保护不移除，旧结构化身份按现有语义退休。
5. 旧账本以叶节点分层删除，每批最多500个绑定参数，父/子不同语句；不开关 FK，不递归，超过现有备份行预算拒绝替换。其余业务表继续原依赖顺序。
6. 重装当前 SchemaGuards；恢复原来已存在但当前安装器尚不认识的保护触发器。定义只取自目标 sqlite_master。
7. 任何预检、清理、写入、后验、提交前异常必须由原事务回滚业务数据、身份和 DDL。明确测试替换后/提交前故障及重新打开数据库。
