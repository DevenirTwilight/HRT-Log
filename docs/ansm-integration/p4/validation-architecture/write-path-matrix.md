The authoritative read/check inventory is auditStagedDataset → stored-column count/type/text fences; validateMeasuredCandidateState → FK/SchemaGuards/ReferenceSchema/LabContext/RegimenHistory/HistoryPeriods/trash/LAB checks; exact-source coverage + event/operation UUID collision; complete chain; each container projection; complete operations/allocations/CONFIRM sets. The cross-table UUID UNION in ReferenceSchema checks syntax only, not universal cross-table uniqueness. The event/operation collision query is a separate application-level rule. No-ledger/no-op operations still affect this audit.

Local candidates must prove preservation of untouched invariants, not just type-valid new rows. Important negative dependencies: absence of an operation UUID collision with reference_event, no prior use for a record revision, no second reversal, no hidden zero-effect operation/capture, no independent count after original use, and aggregate row/text budgets. SQL FK adjacency cannot express these predicates.
