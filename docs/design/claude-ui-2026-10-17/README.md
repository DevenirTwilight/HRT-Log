## 三、关键产品与安全审查

**01 今日卡**：样式突出“下一次”时间和完成按钮很好，但必须覆盖多个同一时刻服药、全完成、没有下一次、过期未确认、改期/跳过/撤销、多时区、月历去重；所有动作沿用现有 Repository 事务。按日期显示的计划与已实际服用事实必须区分。

**02 库存**：图片的“38 mg”“约 9 天”等只是示意。混合药物或不同规格的片、泵、贴、凝胶质量、开封与标签名义容量不能无证据相加；UNKNOWN 不是零也不证明充足。图中按钮不得绕过 P4/P5 的来源确认、库存编码/精确备份、同源预测、事务和启用门。旧库存不能因此静默重算。

**03 治疗时间线**：将将来预约与已发生的里程碑明确分开。逾期预约不自动视为已就诊；无时期旧记录不强行归属当前时期；日期精度与完整顺序、历史冻结快照及 PeriodStabilityTest 保持不变。

**04 抽屉**：保留当前 12 入口、“复诊”独立入口、锁屏/伪装隔离、返回栈以及四语标签。库存红点/数字只在预测有充分证据时显示，不能因 UNKNOWN 创造确定告警。

**05 医疗档案当前态**：现有复诊、问题清单、Visit Pack、化验和时期入口可以聚合。用户显式确认完成就诊，不能只看日期；“PDF 已生成”只能根据真实生成记录展示，不可假定应用已保存 PDF 本体。

**06–07 医疗原件（未来）**：安全加密文件库、锁屏和伪装访问门、原件密文生命周期、真实 PDF/图片解码预览、临时明文、文件系统与 SQLCipher 联合原子性、完整备份/新设备恢复、恶意输入和资源预算、删除/回收/恢复/epoch、API26/29/35 和真实 ARM 等必须按 MED-02 安全计划验收。合成演示和图片不构成生产上线证明。“原件完整性正常”只在真实密文校验通过后显示；它不代表医学内容真实。

**08 就诊资料导出**：截图中“处方照片”和“浓度估算曲线”被标注“默认不选”，但可见勾选和底部“已选 5 项”需要正式审计，不能照着静态图硬编码。一个状态源驱动勾选、数量、目录预览、实际导出。照片、健康原件和文献 PK 曲线默认不含，只有用户当次明确选择与确认才可加入；导出外部副本不再受到 App 本地加密保护。图示“按时 92%”没有定义分母和未知记录规则，不可直接投产。

## 四、视觉设计原则（不是具体 dp 的权威规范）

深青绿主按钮、淡青重点、珊瑚色有解释文字的警告、低饱和底色、大圆角及充足留白；把“下一步”和实际状态放在标题层级，预测与来源注释次级显示。精确 Compose token 需从真实截图及已有 Theme 里复核，不从设计图直接猜像素或取代无障碍对比度。覆盖 320/411dp、1×/2× 字体、明暗主题、长药名、所有四语：简体中文、繁体中文、英文、法文。**没有日语版本。**
