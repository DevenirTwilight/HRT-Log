## 二、页面逐张核查：视觉目标、现状和依赖

### 01 今日优先 / 首页

**样图呈现**：顶栏 `HRT Log` 与日历入口；深青绿色主卡突出今日进度 `1/2 已完成`、下次服药的时间 `21:00`、药名/剂量/途径、单一高可见「现在服用」操作及更多菜单；下方显示已服记录。其后是仅在必要时出现的暖色库存预警，再后是日期视图与 ✓/½/✕/今日图例。

**现有对应**：`app/src/main/java/net/plainnotes/app/ui/CalendarScreen.kt`、`TodayCard.kt`、`StockScreen.kt`；`REQUIREMENTS §96、§101` 已做过今天卡/日历去重，相关真实 Compose 截图见 `docs/ui-audit/2026-10-16-ui04/after/`。不能将此图称为已发布 UI。

**开发参考**：提炼单一主操作、时间视觉层级和“今天卡→真正需要关注的库存→月历”节奏。**必须沿用已验证的实际服药/跳过/改期/未确认回调**；多条同一时刻用药、今日已经全完成、无下一次服药、过期时段、折叠、其它日期和时区/DST 都要处理，不能因为视觉上只有一项就只保留一项。已记录与待确认状态不可以混淆；当日数据只显示一次。禁用任何点击就自动更改个人推荐剂量的行为。

### 02 库存

**样图呈现**：药物分卡、余量大字、估计可用天数、开封中容量进度、未开封包装数、一个突出主按钮、包装记录折叠/展开、警告色、未追踪时的空状态。样例涉及 `38 mg`、`6 mg`、`约 9 天` 和 `约 3 天后用完`。

**现有对应**：`StockScreen.kt`、`core/data` 的 `SupplyLedger`/`StockForecasts`，UI-01 库存主操作优化已有实现。ANSM P4/PR #57 的精确量纲/库存审计正在开发，正式写入开关仍受独立准入门限制；P5 统一预测和界面并非已经完成。

**开发参考**：卡片组织、动作为简洁入口；**不能直接复用图中的 mg 总余额和“够 X 天”声称**，必须由同一个正式安全的预测投影导出。不同药物、不同含量、片/贴/泵/凝胶质量、用户确认实际可用量和旧标量不能无凭据相加；未知不是 0，也不证明可用。库存不足、未追踪、记录错误、规格冲突必须文字区分。隐藏的新计量入口不得被 UI 按钮绕过；旧库存操作行为不能因纯视觉改造变化。

### 03 治疗时间线

**样图呈现**：顶部「全部/化验/就诊/里程碑」筛选、即将发生的就诊卡、按治疗时期组织的当前时期卡、里程碑及化验、无需方案的历史事件、底部图例。

**现有对应**：`CalendarScreen.kt`（预约）、`TimelineEditing.kt`、`app/src/main/java/net/plainnotes/app/timeline/`，已有 `Timeline` / period 模型与 UI-01/UI-02A 筛选基础；时期稳定性受 `PeriodStabilityTest` 保护。

**开发参考**：清晰区分计划中的未来事件、已经发生的事实、用户手动里程碑及系统推导的时期状态；不把“预约日期已过”自动等价于已就诊。事件跨时期、日期级观测、重叠时期/编辑/删除和旧数据缺失时，不制造治疗史。筛选仅影响可见性，不改变排序、记录或业务含义，卡片点击维持已有导航/编辑权限。

### 04 抽屉导航

**样图呈现**：顶层日历、治疗时间线；日常记录（服药记录、身心状态）；用药管理（药物方案、库存、浓度估算）；就医资料（医疗档案、复诊、化验）；设置、关于。库存条目有 1 个告警数字。

**现有对应**：`AppShell.kt` / `REQUIREMENTS §99`，UI-03A 已将抽屉按“信息来源”分组，且保留全部 12 个入口，截图见 `docs/ui-audit/2026-10-15-ui03/after/`。

**开发参考**：多处结构与当前开发成果相似，先逐条比对，**不要为了模仿设计稿重新实现已经完成的抽屉**；保留复诊独立入口、键盘/返回/伪装模式与锁定边界。库存徽标只能表示已验证、可安全解释的告警，不应为不明余量制造误导性数字。

### 05 医疗档案：现阶段

**样图呈现**：下次复诊卡、想问的问题、就诊资料包 PDF 状态、过去日期“去过了吗？”显式确认、按年展示就诊记录、化验和治疗时间线快捷入口、回收站。

**现有对应**：`MedicalRecordsScreen.kt`、`VisitsScreen.kt`、`app/src/main/java/net/plainnotes/app/visit/` 和 `docs/design/medical-records-roadmap.md`。UI-01 G 已实现“医疗档案首页”的部分版式/交互；Visit Pack 已有 PDF 导出能力但**没有因此实现本地原件文件库**。

**开发参考**：这是“**已有记录聚合**”可优先核对的样式，不是授权附件功能。只能通过用户明确确认更新就诊状态；预约日过期不能自动标记已就诊。无数据时提供真实可用的空状态；不得生成不存在的医生、就诊、文件和 PDF。现阶段卡片“资料包未生成”需来自保存的实际生成状态。

### 06 医疗档案：未来文件库（概念功能，非已上线）

**样图呈现**：按标题/机构/类别搜索、添加文件、为就诊准备、待整理计数、按文件类型统计、最近资料、文件与化验/就诊的显式关联、医生机构、医疗原件完整备份状态、回收站/未关联文件。

**现有对应**：`docs/design/medical-records-roadmap.md` 的 B/C/D/E；MED-02 的安全研究、隔离合成演示及待批准生产方案。**当前正式附件写入、原件加密文件库、生产 PDF/图片预览和完整加密附件备份仍不应标为完成。**

**开发参考**：作为未来信息架构/布局示意保留。先满足独立审查和正式授权：AppLock/伪装隔离、文件密文与密钥、SQLCipher+文件系统一致性、PNBAK 原件备份/恢复、权限、临时明文、配额、原子导入、恶意 PDF/图片、删除与 tombstone/epoch、实际 ARM/低内存/重启测试。此前只读样例或 Debug 合成 UI **不可以作为开启生产入口的理由**。不能因为截图上写“12 份文件全部可读”而在真实 UI 中提供相同保证。

### 07 文件详情（概念功能，非已上线）

**样图呈现**：多页预览、样式化 PDF 缩略图/页码、文件类别、采样日期、就诊附加入口、已关联结构化化验项目、来源机构/日期/大小/完整性、备注。

**现有对应**：尚需医疗原件/预览服务安全门；当前 `LabValueEntity` 是结构化化验值，不代表持有对应 PDF 文件。关联应由用户明确选择，不能由相同采样日期或两种激素名称自动推断。

**开发参考**：区分 `用户填写未经独立核验`、`来源事实`、`密文完整性校验通过` 和 `医学内容已验证`；仅在真实校验完成时显示“完整性校验正常”，它**不表示报告医学正确**。PDF/图片查看器只在已解锁且有授权的真实应用上下文内打开，失败/锁定/取消不泄露缩略图、内容或临时缓存；关联改变不重写化验值或旧 Visit Pack 快照。

### 08 为就诊准备资料（面向未来的细化设计）

**样图呈现**：按「就诊与用药 / 化验 / 其他资料」分组的勾选清单、每项来源或状态标签、敏感资料默认不选提示、动态已选计数/估计页数和预览目录；说明导出后的外部副本不受应用控制。

**现有对应**：`VisitPack` / `VisitsScreen.kt` 已支持部分结构化资料的显式选择、生成 PDF；但**截图中的文件原件附带、加密文件库、选择处方照片与文献 PK 图导出**不能由现有 Visit Pack 推定已实现。未来附件能力仍需独立批准。

**高优先级设计风险（需实现时复核，不代表已证实代码缺陷）**：视觉上“处方照片”“浓度估算曲线”标注 `默认不选`，而旁边勾选标志及页脚 `已选 5 项` 与全部可见项之间不容易核对。真实 UI 要求一份状态驱动 checkbox/选择计数/预览目录/实际 PDF、任一变更同步；**敏感照片、文献曲线和未选择的附件默认不得进导出**，除非用户当次主动勾选并确认。贴着 `默认不选` 的徽标不能替代程序默认 false；“按时 92%”只在可解释分母/未知记录规则及真实数据证据齐备时展示，否则 UNKNOWN。必须告知导出 PDF/文件离开应用后的加密与隐私边界。

## 三、从图中可复用的视觉与文案原则（不是像素还原规格）

- **层级**：深青绿主动作、浅青蓝重点标记、暖珊瑚警告、低饱和浅色背景；卡片圆角、大面积留白、明确分组标题；视觉令牌必须在实际 Compose 设计系统中复核再抽取，不凭图推断精确 dp/色值。
- **文案**：让“今天的下一步”“实际记录”“来源未确认”“库存状态未知”易懂；不把计算结果当医疗结论，不说“可靠安全库存”除非有证据。
- **记录与预测分开**：今日服药事实、预计计划、余量投影、测量记录和文献 PK 估算在字体/标签上明确区分。图中数值是示意，不能变成自动校准或产品事实。
- **导航**：沿用已有 12 入口与现有 back stack；新增未来页先走权限/产品准入门，不能“为了看起来完整”做可点击但错误的入口。
- **无障碍和国际化**：目前支持简体中文、繁体中文、英文、法文；**没有日语版本**。覆盖 320/411dp、1×/2× 字号、明暗色、中/高对比度、TalkBack、长药名/长数值、键盘/恢复、状态非仅靠颜色。
- **发布图**：这是**Claude 视觉概念稿**，非当前 APK 截图。社媒宣传如使用，应显著标“设计概念 / 开发中”，不要用此图证明文件库、实盘精确库存或备份功能已可用。真实 App 图需使用同源 Compose screenshot tests 或亲自取得的无隐私真机屏幕，不可用 AI 重画并宣称真实。
