# 设计：时期编辑体系重建（build 25，用户 2026-10-08 已定）

需求见 REQUIREMENTS §40。本文是实现方案。取代 [timeline-manual-editing.md](timeline-manual-editing.md) 的“操作”一节；数据表沿用 schema 9，不升 schema。

## 概念

- **系统时期**：由应用保存的方案版本和服药记录自动识别出的时期。自动规则（14 天、30 天空白、标准相同合并、1 天内更正）只作用于这些部分。
- **用户时期**：`history_period_revision` 中 `kind=PERIOD`、`state=CONFIRMED` 的行。边界和标准固定，不与任何相邻部分合并、吸收或拆开，即使标准相同也单独显示。
- **删除标记**：`kind=DELETED` 的行（在回收站里），其范围内系统部分不显示，记录显示“方案未知”。用户时期可以与删除标记重叠，用户时期优先。
- 旧的 `CONFIRMED`（已确认）和 `FILL` 行只在迁移时读取，迁移后不再参与显示；`STOP` 行保留为停用标记（与删除标记一样只挡住系统部分）。

## 显示规则

1. 用户时期盖住同一种药（同一条目，或与它同一“药物通道”的条目）的全部系统部分；删除标记和停用标记也盖住系统部分。
2. **“至今”的用户时期**（用户 2026-10-08 选定）：在它写入（`evidence_json.stated_utc`）之后保存的方案变化（新版本开始或已有版本结束）结束这段时期；从那一刻起按系统规则显示。写入之前的方案仍被它盖住。
3. 其余部分按原规则合并成时期；用户时期在合并时永远是边界。

## 三个操作

| 操作 | 入口 | 写入 |
|---|---|---|
| 新建 | 时间线顶部“新建时期” | 1 行 PERIOD |
| 编辑 | 每个时期卡片 ⋮ →“编辑”；卡片里的短暂版本行 →“编辑” | 目标范围内的用户行被替换；写 1 行 PERIOD |
| 删除 | 每个时期卡片 ⋮ →“删除”；短暂版本行 →“删除” | 范围内的用户行撤销（范围外部分保留），写 1 行 DELETED；进回收站 |

- 编辑的“目标”是被编辑时期（或短暂版本）中所选药物的范围。目标里没被新范围留住的日期显示系统识别结果（用户 2026-10-08 选定），没有可识别的就显示方案未知。
- 表单：药物、开始日期、结束日期或“至今”、每几天一次、每天几次、每次剂量。精简模式不显示药名和剂量（药物显示为 #1、#2）。

## 重叠：先问再处理

保存前，按同一药物通道找出目标以外、与新范围相交的已显示时期：
- 被完全覆盖 → “将被移进回收站”。
- 一端相交 → “将缩短为 a 至 b”；新范围在中间 → “将分成 a 至 b 和 c 至 d”。

“自动缩短”：一次事务写入——新时期、被缩短的时期剩余部分（系统时期的剩余部分写成用户时期，从此不受自动规则影响；用户时期写新版本）、被完全覆盖的每一段各写一个删除标记并各进回收站（用户时期在恢复时回来）。
“不缩短”：不保存，回到表单，提示先修改相邻那段。不同药物不检查。

## 回收站恢复

恢复时如果会和现有用户时期重叠，拒绝恢复并提示“这段日期已有其他时期，先修改或删除那段再恢复”。回收站里已有的条目（含 build 24 的“我的修改”）保持可恢复。

## 取消“确认”

- 系统识别的时期直接生效；“待确认”不再显示。
- History 的“额外”“剂量与当期不同”对所有生效时期判断（保存方案、用户时期、系统识别）；“待确认时期”标签取消。
- 复诊资料包模板 3：计数中去掉“待确认时期”；已生成的资料包（模板 1、2）不变。
- 新的化验上下文写 `period_source`：`USER_EDIT`（附该用户时期）或 `SYSTEM`；界面标注“用户编辑”或“系统识别”。已冻结的上下文（含旧的“已确认时期”）原样显示。

## 迁移（不升 schema，按数据自动判断）

触发条件：存在生效的 `CONFIRMED` 或 `FILL` 行，或没有 `stated_utc` 的“至今”用户行。打开时间线数据时执行一次，结果写库后不会再触发；恢复旧备份后同样会执行。

1. 用旧规则（与 build 24 相同的投影）算出当前显示。
2. 每个包含 `CONFIRMED`/`FILL`/用户部分的标准段，写一行 PERIOD：范围就是该段显示的起止（非整日处记精确时刻），标准就是显示的标准；该段在现在之后结束的写成“至今”。段内被并入的短暂版本记在 `evidence_json.short_saved`，卡片照旧显示“曾短暂保存为……”。
3. 原 `CONFIRMED`/`FILL` 行和被替换的用户行追加 REVOKED 版本（只追加，不删）。生效的删除、停用标记不动。
4. 升级前后：时期数量、起止、标准、记录归属、History 标签（除了按 §40 取消的“待确认时期”）完全一致。用测试按用户诊断的结构验证。

## 删除的入口和代码

在某天拆开、与下一段合并、删除我的修改、确认这个时期（含编辑已确认时期、撤销确认的对话框）、编辑停用期。对应的仓库函数（confirm/revoke/split/merge/deleteCorrection）删除；`undoTimelineEdit` 只留给回收站恢复。

## 不变

原始记录、冻结快照、库存账本、方案版本、化验上下文、复诊资料包、提醒、PK 模型、公开 Release 和标签。
