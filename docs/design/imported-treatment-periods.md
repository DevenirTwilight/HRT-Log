# 从实际历史识别治疗时期

2026-10-08。用户要求补齐过去方案变化。此前导入摘要只按已有版本日期分组，未构造过去时期，未满足目标。

## 输入与独立设计

读取本项目冻结MedicationSnapshot、实际时间/剂量与保存RegimenVersion。HRT Tracker导出只有实际事件，不能称为已确认处方。独立实现只读识别，不使用竞品实现。

- 以冻结成分、途径、单位、酯和制剂识别药物；唯一匹配保存方案时使用其身份，否则保留原身份。
- 按本地日期汇总实际剂量分布，至少三个一致日形成每日模式；稀疏间隔模式需至少四次一致记录。持续的剂量、途径、制剂、间隔变化形成识别时期。孤立异常保留原记录，不能单独形成新方案；相同模式间最多桥接三个周期的短缺口，不跨已有稳定不同模式。舌下tier只属PK配置，不切临床标准。完全重合的时间/剂量存在歧义，不用于确认新的每日分布。
- 时间覆盖仅到最后证据日后一周期，不跨长空白推断持续治疗；边界是识别的观察覆盖，不是已确认处方生效日期或停药日期。
- 保存方案优先；识别区间裁剪到其未覆盖处。相同标准相邻时由现有V2治疗时期投影合并。识别元数据、来源IDs与保存版本IDs分开，负的投影ID不写数据库/Context1。
- 治疗时期直接展示历史识别方案、出处和原始记录入口；仅未能识别的记录保留待识别入口。

## 兼容与验证

无需schema变更，旧导入即刻生效。不改V1定义/签名、原始记录、库存、提醒、PK、化验冻结上下文。测试合成导入→Room→时期；剂量/间隔/途径变化、孤立异常、长空白、重导入、备份还原、保存版本优先与身份归并。
