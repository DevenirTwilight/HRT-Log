## 0　负责人的原话和决定

负责人看着真机截图说：“这个是不是有点太素了？给升级一下。” 现在的页面：顶部一个满宽的深青绿大按钮“记录已发生的就诊”，下面是纯文字的灰卡片，医生、地点、时间挤在三行文字里，右下角“就诊预约”浮动按钮。要求：**更美观、层次清楚，但仍是青绿主色，点缀色只做小面积**。样图已按此画出，照样图做，不要自己加功能、开关或说明文字。

## 1　范围

**只改复诊列表页**（`VisitsScreen` 的列表分支与 `VisitCard`）。复诊**详情页**（`VisitDetail`）、新增/编辑就诊对话框、就诊资料包、问题清单、导航和返回行为**本次都不改**，除了它们自然继承 UI-13 的底色。`medical` 模式（医疗档案里复用本页）与普通模式使用同一个新列表，原有参数、回调、`testTag`（如 `visits-record-past`）全部保留。

## 2　页面结构（样图为准）

自上而下：

1. **顶栏**：菜单 + “复诊”，不变。
2. **大卡**（青绿 `primary` 底，圆角 32dp，白字，右上角两个半透明的装饰圆/圆角方块，纯装饰、不读出）：
   - 小标签：有未来的就诊时写“下一次就诊”，否则写“上一次就诊”。
   - 大号日期（如“11月20日”）。同一行右侧一个半透明小标签：未来写“还有 N 天”，过去写“距今 N 天”，当天写“今天”。**这一行是样图新增的，负责人看过没有反对；若实现中发现天数计算有歧义，就按下面第 3 条规则做，不要自己改含义。**
   - 星期、时间、科室（如“周五 14:00 · 内分泌科”），再一行“医生 · 机构”（缺哪个就省哪个，都没有就整行不显示）。
   - 底部一个**白色胶囊按钮**“＋ 记录已发生的就诊”（文字用青绿），整行宽度，高度 ≥ 52dp。它取代原来页面顶部的深青绿大按钮，**点击行为、`testTag("visits-record-past")` 完全不变**。
3. **分组标题**：有未来的就诊时先显示“即将到来”，再显示“已过去”，“已过去”右边一个小数量标签（青绿容器，如“2”）。分组名沿用现有字符串 `visits_upcoming` / `visits_past`。
4. **就诊卡片**（`surfaceContainerLow`，圆角 28dp，内边距 16dp，卡片之间 12–14dp）：
   - 左：58dp 宽的**日期方块**，蓝色点缀（容器色 + 容器上文字），三行：月份（小）、日期（大，粗）、星期（小）。
   - 右上：科室作标题（沿用 `choiceLabel(type)`），同一行右端是时间（青绿，粗）。
   - 医生一行：人形小图标（蓝色点缀）+ 医生。地点一行：定位小图标（蓝色点缀）+ 地点，**最多两行，超出省略；TalkBack 读完整内容**。没有医生或地点就省略那一行。
   - 标签行（可换行）：已确认 = 带勾的 success 语义色标签，文字沿用 `visit_completed`；未确认 = **虚线描边**的标签，文字沿用 `visit_not_confirmed`（用 UI-06 的 unconfirmed 语义）；问题数 = 蓝色淡底小标签，沿用 `visit_question_count`；已生成资料包 = **紫色**容器色小标签（负责人明确要求：与问题数的蓝色区分；这是本页唯一的第二种点缀色，面积只有一个小标签，不得扩大到别处），文字沿用 `visit_last_pack` 的信息（样图写“已生成资料包”，若需要显示日期以 `visit_last_pack` 为准，二者选其一并在报告说明）。有几个显示几个，没有就不显示。
   - 整张卡片可点击，进入原来的详情页，行为不变。
5. **右下角“就诊预约”浮动按钮**：位置、点击行为不变，颜色用青绿容器（`primaryContainer`，与首页“添加”一致），不再单独用别的色。
6. **空状态**（没有任何就诊）：沿用现有 `EmptyState` 和“就诊预约”按钮；顶部仍要有“记录已发生的就诊”入口（可以是同样的白色胶囊放在一张青绿大卡里，大卡文字写现有 `visits_empty`，不新增文案）。

## 3　大卡显示哪一次（逻辑要写成纯函数并单测）

- 有未来的就诊（`at_utc >= now`）：取最早的一次，标签“下一次就诊”。
- 否则取**已确认就诊（`completed_utc != null`）里最近的一次**，标签“上一次就诊”。未确认的过去就诊仍在下面“已过去”列表里，用虚线“未确认”标签，但不进大卡。
- 两者都没有：大卡退化为空状态（第 2 节第 6 点）。
- **天数**按**就诊所在时区的日历日**计算：`medical` 模式用该就诊的 `at_zone`，普通模式用系统时区（与现在卡片显示时间所用的时区一致，不得出现卡片显示一天、天数按另一天算）。今天 = 0 天（显示“今天”）。夏令时切换日、跨年、跨月、时区不同于系统时区都要有测试。
- 不新增“频率提醒”“该预约了”之类的话。天数只是已过去或还剩的时间。

## 4　字符串与无障碍

- 新字符串要补**四个语言目录**：`values`（英文）、`values-zh`（简体）、`values-b+zh+Hant`（繁体）、`values-fr`（法文）。新增的只有：大卡标签“下一次就诊 / 上一次就诊”、天数标签（“还有 %d 天 / 距今 %d 天 / 今天”，注意复数）、“记录已发生的就诊”沿用 `medical_add_visit`。其余全部沿用现有字符串。
- 日期方块不读出三段碎文字：给整张卡片一个完整的无障碍描述（日期时间、科室、医生、地点、状态、问题数、资料包），装饰图标 `contentDescription = null`。
- 状态不得只靠颜色：已确认有勾和文字，未确认有虚线和文字。点缀色元素旁边都有文字或图标。
- 触摸目标 ≥ 48dp，卡片最小高度不因省略而塌陷。

## 5　测试与证据

1. 纯函数单测：大卡选哪一次、天数、当天、夏令时、跨时区（见第 3 节）。
2. Compose 测试（Robolectric）：有未来 / 只有过去 / 全空 / 有未确认的过去就诊，四种状态下大卡标签、分组标题、卡片标签（已确认、未确认、问题数、资料包）都出现且文字正确；`visits-record-past` 仍可点并触发原回调；点卡片进入详情；`medical` 模式也走同一布局。
3. 布局：四语 × 320/411dp × 浅/深色 × 字号 1、1.3、2，没有文字被裁切、重叠或越窗；地点两行省略后整张卡片仍可读；纳入现有布局回归（`Ui09Test`、`Ui09ScreenshotTest`、`MedicalAttachmentUiGuardTest` 里引用 `visits-record-past`、`VisitsScreen` 或复诊页字符串的断言要更新并说明“旧含义 → 新含义”，不得删除或放宽）。
4. 对比度：大卡白字对青绿、标签文字对其底色、紫/蓝点缀沿用 UI-13 的对比度测试（蓝与紫两套都要测），浅/深色 × 标准/中/高对比度。高对比度下点缀图标用 onSurface。
5. **合成数据**做前后对比图：现状 vs 新版，覆盖“只有过去两次”“有一次未来 + 两次过去”“一次未确认的过去就诊”“一个很长的地点（两行省略）”。浅色与深色、411dp 与 320dp、字号 1 与 2、简体与法文。注明源码 SHA 和生成方式。TalkBack / 真机未执行就标 NOT_RUN。**不得使用真实就诊、医生、机构信息**，负责人手机截图里的内容不能进仓库或测试。
6. 不把 AI 自评或“能编译”当作验收，由负责人看真机或对比图确认。
