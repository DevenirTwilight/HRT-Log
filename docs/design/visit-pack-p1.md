# P1 Visit Pack：复诊资料包与“上次复诊以来”事实摘要

2026-10-07。用户要求接手后继续开发；按[路线图](../hrt-roadmap-2026-10-07.md)下一优先项实施，扩展现有预约与复诊摘要PDF，不重新造预约模块。schema5→6，versionCode11，只维护full、沿用原正式签名，无公开发布，不改PK参数或公式。设计依据本项目[纵向记录设计](longitudinal-hrt-record.md)第5节，独立实现，不复制竞品界面或代码。

## 问题

- 预约只能新建：不能编辑、删除、确认是否已就诊，也没有可查找的列表（只在日历当天和时间线出现）。
- 复诊摘要PDF只能选日期，不知道“上次就诊”在哪；内容固定全部输出，用户无法挑选给医生看的部分；导出后没有记录生成过什么。
- 想问医生的问题只能写在备注里，不能逐条勾选、记回答。

## 数据（schema 6）

- `appointment` 新增 `completed_utc INTEGER NULL`：用户明确点“确认已就诊”时写入当前时间；为空表示未确认。**不根据预约时间已过自动推定已就诊。**撤销确认清空该列。
- `visit_question`：id、appointment_id（FK→appointment，CASCADE）、sort_order、text（去空白后非空）、status（`OPEN` 未问 / `ASKED` 已问）、answer_note（可空，用户自己记下的回答）。
- `visit_pack`：一次导出的元数据，**生成后不可修改**（触发器禁止UPDATE）。id、appointment_id（FK，CASCADE）、generated_utc、zone、range_from/range_to（含首尾的本地日期）、sections（排序后逗号列表）、language、template_version（1）、input_digest（64位十六进制SHA-256）、facts_json（摘要计数）。不保存PDF本身；PDF只写到用户选择的位置。重新生成是新的一行。
- 删除预约须确认，同时删除其问题和资料包记录；已导出的PDF文件不受影响，确认文案说明这一点。
- 备份：新表加入`DOMAIN_TABLES`；schema1–5备份缺新表/新列可恢复（新列为空、无问题和资料包）；schema6要求新表。恢复校验sections只允许已知值、日期合法、from≤to、digest格式、facts_json为对象且受JSON预算约束；失败整体回滚。

## 界面

- 新导航页“复诊”：即将到来 / 已过去两组预约卡片，显示类型、时间、医生、地点、问题数、是否已确认就诊、最近一次资料包时间。日历当天卡片和时间线预约条目点击进入同一详情。
- 预约详情：编辑（复用预约对话框，带原值）、确认已就诊/撤销、问题清单（新增、改文字、标已问、记回答、上下移动、删除）、“生成复诊资料包”、已生成记录列表、删除预约。
- 生成对话框：
  - 区间默认从**上一次用户确认已就诊的预约日期**到本次预约日期（本次在未来则到今天）。找不到时明确显示“未找到已确认的上次就诊”，默认最近90天，必须由用户确认或修改。区间不得晚于今天。
  - 内容勾选（与区间无关的默认值）：事实摘要✓、当前方案与方案变化✓、服药记录✓、化验与采样上下文✓、症状记录✓、阶段回顾✓、每日状态✓、问题清单✓；**包装来源/批号、用户里程碑默认不勾选**，需显式选择（可能含手术等私人信息）。
  - 预览：实时显示事实摘要文字，与PDF使用同一函数。
  - 导出：系统文件选择器（伪装模式文件选择器例外照旧），同一数据库事务读取 → 写PDF → 成功后插入`visit_pack`记录。写入失败不留记录。

## 事实摘要（确定性模板）

纯函数`VisitFacts.build(data, from, to, zone)`，只计数和列出已保存事实：

- 区间天数；本区间开始/结束的方案版本数（按`regimen_version`冻结快照，不用当前药名重绘历史）；
- 每种药：已记录服药（按实际时间，含迟服数、导入数）、确认漏服、跳过、**未登记（自动未确认，不等于漏服）**（按计划时间）；
- 化验次数与项目；有症状记录的天数与不同症状组数；阶段回顾次数；每日状态记录天数、备注天数；区间内其他预约数；里程碑数（仅当勾选里程碑时列出内容）。

不写“依从性好/差”、不算百分比评分、不判断正常/异常/趋势、不推断因果、不给剂量建议；零也照实写零。未登记与确认漏服始终分开。

## PDF

复用现有`PdfReport`分页/文字绘制，按勾选输出：标题（本次预约类型/时间/医生，可不填）与区间、生成时间、校验摘要前12位；事实摘要；当前方案与区间内方案版本；服药统计与当时记录的配置；化验原值/参考范围/冻结采样上下文；症状（来源快照）；阶段回顾；每日状态折线与备注；问题清单（状态与用户回答）；可选包装来源批号（标注“当前包装信息，不代表区间内变化”）与里程碑；页脚“不是诊断”。不勾选的部分完全不出现。不加颜色判读，不包含浓度曲线（浓度页另有导出）。

`input_digest`：对模板版本、语言、区间、勾选项以及纳入的各行记录（按id排序的字段值）做SHA-256，便于用户核对“这份PDF对应哪条记录”；不是加密签名或防篡改证明，界面不这样宣称。

## 不做（本批）

结构化医生档案、检查/化验清单模板、PDF在应用内留存或预览图、自动“趋势”文字、批号历史事件（当前只有包装当前值）、阶段/里程碑专属CSV。浓度曲线不进入资料包。

## 验收（合成数据）

- 5→6迁移保留原预约；1→6、4→6原生迁移；schema5备份恢复后新表为空；新备份往返保留问题、确认状态与资料包记录；恶意sections/digest/日期被拒且回滚。
- 默认区间：多个预约中只取早于本次且已确认的最近一次；未确认的过去预约不作为起点；无记录时标明。
- 事实计数：区间首尾边界、实际时间与计划时间分别归属、删除记录排除、未登记与确认漏服分开、导入计数、方案版本不受当前药名改动影响。
- 勾选：未勾选部分不进入PDF与digest；包装/里程碑默认关。
- digest：同一输入稳定，改动纳入记录或勾选即变化。
- 资料包记录不可UPDATE；删除预约级联删除问题与资料包记录。
- 四语文案齐全（TranslationsTest）；原生PDF分页用例加入资料包。
