# P0 实施：历史上下文、未登记语义和有界恢复

2026-10-07，用户已要求开始更新应用。本次落实研究路线图P0的应用部分，不发布、不选项目许可证，不复制竞品实现。P1 epoch/timeline/visit pack后续分批实现。

- 用药快照：扩展已有config_snapshot，带版本/完整PK profile；新计划与实际事件都保存。计算、历史显示、CSV/PDF读取事件快照，未来读取规则快照。旧快照只使用确实保存的成分/单位/途径/酯；需要未保存制剂参数时跳过并说明，不按当前profile补猜。保持当前体重规则，不改PK公式/参数。模型bundle可重现版本包留待后续。
- 症状：schema3新增nullable context_snapshot；首次勾选在同一读取事务内按当前药物匹配，保存目录版本、名称、药物快照、匹配来源原文/版本/链接和记录时间。备注修改保留原snapshot；删除后重新勾选是新观察。旧记录NULL表示当时上下文未知，PDF不附当前目录所有来源。
- 未登记：保留旧存储status=MISSED/origin=AUTO_MISSED兼容备份；领域/界面映射UNCONFIRMED。明确用户确认后转APP/MISSED，服药补记继续可用。统计分列，存在未确认不显示完整服药率；不猜旧IMPORT_TM状态。
- 备份：容器32MiB上限、明文32MiB上限、嵌套32层、单字符串1MiB、总行100000的保守资源预算；输入流有限读取、JSON结构扫描在全量JSONObject前。恢复列/类型按当前schema白名单；旧schema允许缺新列；全量约束/日期/关联/账本业务检查在原事务内，任何失败回滚。固定Argon2id和PNBAK1保留，不新增压缩/可变KDF。
- 兼容：迁移2→3仅增加症状列，不虚构历史；schema1/2备份继续升级。versionCode增加到6，版本名沿用0.2.0。所有新提示四语。验证使用合成数据，覆盖编辑profile不改历史、导入保留原配置、来源变化不重解释、未确认统计、畸形恢复回滚、旧备份与迁移。

32MiB文件限额不是可证明的总堆预算；多副本/KDF仍占内存。当前无图片附件，一旦多年数据超过限制应明确提示而非截断；未来分块协议另行设计。

实施复核：导入记录的途径为空时不继承当前药物途径或应用口服假设，相关曲线标为历史上下文缺失。既有native非E2录入尚未开放途径选择，原口服模型假设保持；真正通用route建模另行设计。包装仍未持久化自身单位，P0只阻止已知历史单位与当前单位不同的补记自动扣减，不能声称解决了所有库存量纲迁移问题。
