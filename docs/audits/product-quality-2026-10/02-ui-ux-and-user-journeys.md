# 02 UI/UX、信息架构与核心用户任务（阶段 B，2026-10-12）

**方法说明**：这是**专家启发式审查**，依据源码、仓库已提交截图（`docs/ui-audit/`，标注了日期）和已有 UI 审计文档，**不是用户研究**。本容器无 Android SDK 和设备，无法生成新截图。点击步数是按源码路径数出来的，未在真机上计时。每条发现标注类型：

- **[确认]**：源码或测试直接证明的问题；
- **[风险]**：有具体依据，但未复现；
- **[建议]**：用户体验优化；
- **[候选]**：未来功能。

## 1. 信息架构

### 1.1 现状

11 个一级入口在同一个抽屉里平铺（`AppShell.kt:34-46`）。没有底部导航，没有“今天”专用页，日历兼任首页。

按用户心智可以分成四组：

| 组 | 入口 | 使用频率（推断） |
|---|---|---|
| 每日执行 | 日历（首页）、库存、身心状态 | 每天 |
| 历史与事实 | 历史、时间线、化验 | 每周～每月 |
| 就诊与解释 | 复诊、血药浓度 | 每月～每季度 |
| 配置 | 药物、设置、关于 | 偶尔 |

### 1.2 发现

- **[确认] 返回键直接退出应用**：任何页面按系统返回都会 `finish()`（`MainActivity.kt:63-65`），伪装模式下退回外壳。只有复诊详情拦截返回（`VisitsScreen.kt:44`）。
  - 用户从“化验”按返回期望回到日历，结果整个应用关闭。下次打开还需重新解锁（取决于锁定时间）。
- **[确认] 重复内容和三处入口**：
  - “历史”和“时间线”都展示服药记录：时间线卡片菜单“查看记录”跳到历史页，并带选中集合（`LongitudinalScreen.kt:192`）。
  - “药物”和日历 FAB 都能添加药物。
  - 预约在“日历”“复诊”“时间线”三处出现。
  - 这些多为有意的交叉链接，但缺少一句话说明各页职责。
- **[建议]** 首页（日历）同时承担四件事：当日任务、月度回顾、库存预测、待审核横幅。见 §3.1。
- **[确认] 简洁模式只在在用药物 ≤1 种时生效**（`AppShell.kt:136`）。用户开启后加了第二种药，简洁模式会无提示地失效。设置页有 `simple_mode_unavailable` 文案，但正在使用的页面上不会提醒。

### 1.3 两个候选方案（不自动实施，需产品负责人决定，见 07）

**方案 A：保守优化**。不改导航结构和模块：

1. 返回键先回到日历，在日历上再按返回才退出；伪装模式保持现有行为。
2. 抽屉按 §1.1 分 3 组，加小标题。
3. 日历默认视图改为“日”，或在月格上方加“今日待办”摘要（见 §3.1）。
4. 各页顶部加一行职责说明，例如“历史 = 每次记录；时间线 = 方案时期”。

成本低（S～M），只改 UI，不动数据。

**方案 B：结构性改版**：

1. 底部 4 个标签：今天 / 记录（历史 + 时间线合并为两种视图）/ 健康（身心 + 化验 + 浓度）/ 就诊（复诊，未来的医疗档案）。
2. 药物、库存、设置放入“我的/管理”。

收益更大，但影响全部导航测试和截图审计，并与 REQUIREMENTS §42“保留独立复诊入口、不移动导航”的现行决定冲突，必须由用户重新授权。

## 3. 逐页诊断

结论分为五类：保留 / 精简 / 合并 / 延后 / 不应修改。

### 3.1 日历（首页）

- **结论：精简**。
- **[风险]** 默认 `CalView.MONTH`（`CalendarScreen.kt:51`）。一屏依次排列：审核横幅、四段视图切换、月格、图例、当日标题、当日卡片、库存预测卡。每天最主要的操作（确认今天的剂量）不在首屏顶部。
  - 建议：月格上方加一张“今日”摘要卡（待服 n、下一次时间、一键完成），或者把默认视图改成“日”。
- **[确认] 状态只靠颜色表达**：月格和年格的 `DayCell` 用背景色表示已服/部分/漏服/计划（`CalendarScreen.kt:163-179`、`206-234`）。格子是可点击的 `Box`，没有 `contentDescription`/`semantics`，TalkBack 只能读出数字。图例本身也不可聚焦关联。属于可访问性缺陷。
- **[确认] 性能**：`CalendarDateBadge` 在每个日期格每次重组时最多测量文字 20 次（`CalendarScreen.kt:384-387`），月视图 42 格。目前没有卡顿证据，记为低优先级。
- **[UNVERIFIED]** 2.0 字号下两位数日期被裁属于历史问题，已改代码，需截图复核（01 §6）。
- **保留**：周视图的时间列表、年视图热图、缺货图标。

### 3.2 药物 / 药物编辑器

- **结论：保留**，局部精简。
- **[建议]** 菜单文字是“删除”，图标却是归档，实际行为也是归档（停用并停止规则）。改为“停用/归档”，并在已归档药物上提供“恢复使用”。
- **[建议]** 编辑器的 PK 段（凝胶产品、舌下档、贴片释放）对不使用浓度页的人是负担，可折叠为“可选：用于浓度估算”。

### 3.3 库存

- **结论：精简**。
- **[确认] 三种口径**：
  1. 库存页“约 N 天”用当前规则的平均日用量（`StockScreen.kt:30-51`），不考虑改期/跳过/剂量覆盖，`EVERY_N_HOURS` 还忽略分时剂量；
  2. 日历预测卡逐个走已展开的待服槽（`CalendarModel.kt:47-56`）；
  3. 通知用“未来 7 天所需量 > 剩余”（`StockAlerts.kt:29-41`）。
  - 结果：库存页的“库存低”标签（`<7 天`，平均口径）和系统通知（逐槽口径）可能出现一个提示、另一个不提示。BACKLOG 已记录前两种口径；第三种和“标签与通知不一致”是本审计新增。建议统一为逐槽口径，并在 UI 上写明“按已安排剂量计算”。
- **[确认]** 卡片下方列出该药**所有历史包装**，包括已用完/丢弃的，按 id 倒序，每个都有“包装详情”按钮并显示内部 `#id`（`StockScreen.kt:65-70`）。随着时间推移列表无限变长。截图 `docs/ui-audit/2026-10-08-stock-after.png` 已能看到“#2 · 30 mg / #1 · …”。建议默认只显示在用和未开封的包装，历史包装折叠，并去掉 `#id`。
- **[候选]** 包装出厂有效期、注射 mg/mL 换算（BACKLOG 已列）。

### 3.4 历史

- **结论：保留**。
- **[确认]** 已跳过的记录不可点（§2 S3）。
- **[建议]** 依从率在存在任何“未确认”时显示“—”（`HistoryScreen.kt:48`），但没有解释原因。旁边已有“未确认 n 条”，可补一句“确认后显示比例”。
- **[建议]** 范围选“全部”且导入多年数据时，每次重组都会全量过滤排序（`HistoryScreen.kt:63`，未 `remember`）。

### 3.5 时间线

- **结论：精简**（§42 已精简过一轮，继续往同一方向推进）。
- **[建议]** 顶部固定显示“查看时区：Europe/…”（`LongitudinalScreen.kt:92`）。对不跨时区的用户这是技术细节，可只在检测到多时区记录时显示。
- **[建议]** 非简洁模式的卡片同时列出：停药、变更类型、标准方案、“推断”标签、槽位未知、短期保存版本（各带编辑/删除按钮）、同日多段、重建说明（`LongitudinalScreen.kt:128-178`）。建议卡片只保留日期范围 + 方案摘要 + 一个“有 n 处变化”的提示，其余进详情对话框。
- **不应修改**：时期引擎、归属规则、冻结快照，以及 `PeriodStabilityTest` 保护的行为。

### 3.6 身心状态

- **结论：保留**。
- **[确认]** “症状”标签的日期按钮显示原始 `2026-10-12` 字符串（`WellbeingHub.kt:27`），没有走 `formatDate`，四语下都不本地化。修复很小（S）。
- **[建议]** 服药后的提示条（`AppShell.kt:116-121`）每天一次，可在设置关闭（已有），没有“打卡惩罚”设计，符合要求。

### 3.7 化验

- **结论：保留，扩展**。
- **[确认]** 单项录入（S7）。
- **[建议]** 趋势图始终是全时间范围（`LabsScreen.kt:60-79`），可加 1 年/全部切换。参考范围只取最近一条带范围的记录，图上应注明“参考范围来自 yyyy-mm-dd 的结果”（目前只有通用说明 `lab_range_note`）。

### 3.8 血药浓度（默认分支 vs PR #19）

- **默认分支**：顶部免责声明，紧接着是大号“当前估算 xxx pg/mL”（`displayMedium`，`ConcentrationScreen.kt:89-102`），下面是“群体估算/已按化验校准”。数字是视觉中心。
- **PR #19**：标题改为“M2 文献参考浓度”，数字仍是 `displayMedium`。顶部仍保留 Legacy 文案“基于群体平均参数的估算……”（PR 未改 `pk_disclaimer_short` 的位置），紧接着又是 M2 的“Price 图 1 群体幅度情景……B=24、A=434.8 pg/mL”等研究术语（`strings_unified_concentration.xml`）。同一屏有两套口径的说明，且对普通用户术语密度很高。
- **[风险]** 大号 pg/mL 数字配“参考浓度”字样，用户仍容易读成“我现在的血药浓度”。实际化验点叠加在 M2 文献曲线上（图例“实际化验 · 未用于 M2 拟合”），视觉上会引导用户比较“模型 vs 我的化验”，而两者并未校准。详见 03 和 07 的决策项 D-1。

### 3.9 复诊

- **结论：保留**（§42 决定）。
- **[建议]** 生成记录显示 `input_digest.take(12)`（`VisitsScreen.kt:128`）。对用户无意义，可移入“技术详情”。
- **[确认]** 问题删除为硬删除，不进回收站，与其他实体不一致。
- **[确认]** 导出前没有明文提示（04）。

### 3.10 设置

- **结论：精简**。一页里有外观、语言、可靠性检查、身心提示、地区、隐私/锁、伪装、数据（导入/导出/备份/清除）、回收站，没有分组导航，长页滚动。建议拆为二级页面：外观与语言 / 提醒可靠性 / 隐私与安全 / 数据与备份 / 回收站。
