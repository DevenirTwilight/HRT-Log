- 状态种类（`StatusIconKind`）、尺寸档位（`StatusIconSizes`）、调用点、语义键 `StatusIconKindKey`、测试 tag 全部不变。
- 只改 `statusIconSpec` 和 `drawStatusIcon` 的外观规则，以及相应的测试和截图。

不改：状态判定、语义色令牌值（UI-06）、日历格底色（UI-06）、动效（UI-07）、分组列表、强调字体、任何数据和逻辑。

## 2. 纯线条规格

| 状态 | 绘制 | 颜色（见第 3 节的取色规则） |
|---|---|---|
| 已服（TAKEN） | 勾 | success |
| 部分完成（PARTIAL） | 细圆环，右半边实心（半圆饼） | success |
| 漏服（MISSED） | 叉 | missed |
| 跳过（SKIPPED） | 短横 | skipped |
| 未确认（UNCONFIRMED） | 问号（弧线加圆点） | unconfirmed |
| 今天（TODAY） | 保持现状：细实线环加中心圆点 | 调用方传入的 `ring` |

- **线宽**：直径的 8%（40dp 时 3.2dp），最小 1.5dp。比实心圆版本更粗，因为没有底色帮助识别。
- **图形占比**：勾、叉、横、问号在 40dp 时约占直径的 60%，比现在略大，在 18dp 下仍可分辨。部分完成的圆环外径约为直径的 60%。
- 所有线条使用 round cap / round join。
- 删除 `fill`、外圈 `stroke`、`dashed`、`thinStroke` 相关的绘制分支。删除前确认没有其他代码依赖这些分支。`StatusIconSpec` 可以精简，但公开调用方式（`StatusIcon(kind, size, modifier, ring)`）保持不变。

## 3. 取色规则（重点：对比度）

没有了底色，线条直接画在所在的背景上，所以颜色要按背景选择：

- **默认**：用该令牌的 `accent`（浅色主题：已服 #006A63、漏服 #7A6A63、跳过与未确认 #6F7977）。
- **背景是该状态自己的着色日格时**（UI-06 的日历格会用 success、missed、skipped 的 container 作底色）：改用该令牌的 `onContainer`。原因：实测深色主题下，跳过的 accent #889391 画在跳过日格 #3F4947 上只有 2.94:1，不达标。
- **背景是主色时**（今天卡、今天日格）：用 `onPrimary`。今天卡“今天的记录”和“已记录”的勾目前通过 `ring = c.onPrimary` 传入，改为对应的“线条颜色”参数。可以为 `StatusIcon` 增加一个可选参数，例如 `tint: Color? = null`，由调用方覆盖颜色。只在确有需要的调用点使用。
- **高对比度模式**：线条一律用 `onSurface`。线条落在主色背景上时用 `onPrimary`。
- 动态取色开启时，规则同 UI-06：success 跟随动态主色，其余令牌颜色固定。

**验收**：每一个调用点，在浅色、深色 × 标准、中、高三档对比度下，线条与其实际背景的对比度都要 ≥ 3:1，并用参数化测试覆盖。调用点包括：今天卡、今天的记录、确认卡、最近 7 天、月/周/年日格、图例、服药记录、时间线。测试中列出每一组“背景色 × 线条色 × 实测比值”。

## 4. 可辨识性

纯线条远看的区分度较低，必须保证以下几点：

1. **状态文字不能删**：所有列表行、记录行、确认卡上的状态文字保留，例如“已服”“你跳过了”。
2. **形状本身可区分**：勾、叉、横、问号、半圆形状各不相同。灰度截图下 5 种状态能分辨，用截图测试比对。
3. **日历格**：保留 UI-06 的着色底色，图形只是辅助；TalkBack 朗读不变。
4. **18dp 最小尺寸**：图形在 1× 和 2× 屏幕密度下都不糊、不粘连。截图检查 18dp 的 5 种状态。
