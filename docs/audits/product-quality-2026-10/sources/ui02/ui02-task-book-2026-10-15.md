## 2. PR-A：UI-02A

### A1. UI-01 收尾（负责人决定）

- **首页库存卡加“添加库存”**：
  - 每行在“查看库存”之外增加“添加库存”。
  - 它打开 AppShell 中现有的 `AddStockDialog`，即与库存页同一个 `addStock` 状态和 `model.addContainers` 接线。
  - 不复制对话框，不新增写入路径。
  - 行内两个按钮在 320dp、2× 字号下放不下时纵向排列（复用 `AdaptiveActions`）。
- **时间线类型筛选 chip**：顶部加“全部 / 化验 / 就诊 / 里程碑 / 其他”。
  - 纯前端过滤，不改投影。
  - 选中状态用 `rememberSaveable`。
  - 每个 chip ≥48dp 触控高度，选中状态有语义（`selected`）。
- **对比度模式验收**：用 UI-01 的 `Ui01ScreenshotTest` 增加中对比度、高对比度两种模式（zh-CN 与 en × 411dp × 字号 1 × 明暗），覆盖 UI-01 的 5 个页面和本轮新页面。并对今天卡、低库存卡、事件类型徽标、日历标记做 WCAG AA 对比度断言（正文 4.5:1，≥24px 或粗体 ≥18.7px 为 3:1）。不达标的按 `NotesTheme` token 修正。

### A2. 设置页拆成子页面（`SettingsScreen.kt`、`AppShell.kt` 的接线，必要时新文件 `SettingsPages.kt`）

现状：设置是一个长页面，依次叠放提醒可靠性、外观、身心状态、语言，以及 AppShell 传入的地区、隐私与安全、伪装、数据、回收站。

改为**设置总览 + 子页面**。总览为分组列表，每行包含：图标、标题、一行当前状态摘要、右箭头，≥56dp。

| 子页面 | 内容（全部为现有 section 原样迁入） | 总览摘要示例 |
|---|---|---|
| 提醒 | 精确闹钟/通知/电池三项检查、厂商说明、测试提醒、高可靠性开关、可靠性限制说明 | “全部正常”或“2 项需要处理”（tertiary 色 + 文字） |
| 外观与语言 | 主题、动态取色、对比度、语言 | “跟随系统 · 简体中文” |
| 身心状态 | 服药后提示开关、地区 | 地区名称或“未设置” |
| 隐私与安全 | `PrivacySection`（应用锁、简洁模式等）、`DisguiseSection`（仅 full 变体） | “应用锁已开启”/“未开启” |
| 数据与备份 | `DataSection`（导入、导出、备份、删除全部数据） | 最近一次备份时间，或“从未备份” |
| 回收站 | `RecycleBinSection` | 条目数 |

规则：

- **只搬位置，不改行为**：每个 section 的 composable、回调、对话框、测试 tag 保持不变，只是换到子页面里渲染。
- 若“提醒”检查结果在总览和子页面都需要，必须来自同一份状态（现有 `resumeRevision()` 刷新机制），不得各算各的。
- **返回键**：
  - 子页面 → 设置总览 → 日历。
  - 抽屉打开时先关抽屉，对话框仍最优先。
  - 伪装模式与应用锁下的返回行为完全不变（§80 R-06）。
  - 补充 `AppShellBackNavigationTest` 用例。
- 子页面的选择状态用 `rememberSaveable`，旋转或进程重建后停留在同一子页面。
- 顶栏：子页面显示返回箭头和子页面标题，不显示抽屉菜单按钮。
- “删除全部数据”所在的数据页保持现有的确认流程、失败提示与 `stock_alerts` 清理（§95），`LocalDataWipeCoverageTest` 不得放宽。
- 伪装外壳内不出现任何新入口；`ShellPrivacyBoundaryTest`、`PrivateBoundaryTest` 通过。
- “关于”仍是抽屉里的独立入口，不并入设置。

## 3. PR-B：UI-02B · `NotesApp` 状态拆分（纯重构）

目标：`AppShell.kt` 的 `NotesApp` 只负责导航、抽屉、顶栏和 Scaffold；各页面的对话框与临时 UI 状态移到页面自己的宿主中。

- **按页面建宿主**：如 `CalendarHost`、`StockHost`、`HistoryHost`、`MedicalHost`、`LabsHost`。每个宿主持有本页的对话框状态，例如：
  - 库存：`addStock`、`checkStock`、`managePackages`、`restorePackage`、`undoPackage`、`packageInfo`；
  - 历史：`editRecord`、`deleteRecord`、`batch`、`manual`。

  跨页面共享的状态（`completeEntry`、`overrideEntry`、`afterIntake()` 的身心提示、snackbar、`destination`、`visitId`）留在 AppShell，或以明确的参数或回调传入。
- **可选**：用一个 `sealed interface AppDialog` 统一表示当前对话框，保证同一时刻最多一个。若采用，必须证明现有流程中没有需要两个对话框叠加的情况（如对话框中再开日期选择器的属于子对话框，不受影响）。
- **不改** `NotesViewModel`、仓库、数据类、任何 PK 相关文件；不改字符串；不改任何可见布局。
- **硬性验收：本 PR 不允许修改任何既有测试文件中的断言**。仅允许因 composable 移动而修改 import 或调用方签名；每一处修改都在报告中逐条列出并说明为何不影响语义。
- 截图对比：用 `Ui01ScreenshotTest` 在重构前后各生成一次（zh-CN、en × 320/411dp × 字号 1/2 × 明暗），逐张比较，要求像素一致。若有差异，找出原因修正，不得接受差异。
- 进程重建：旋转或进程重建时，原先用 `rememberSaveable` 保存的状态（`destination`、`visitId`、`summary`、`medicalOrigin` 等）语义不变；原先用 `remember` 的保持不变，不借机“顺便”改成可保存。
- 通知入口（`notificationSlot`）、复核横幅、PK 免责声明首次弹出、医疗保存失败的 snackbar 等跨页面流程都要有测试覆盖；现有测试未覆盖的，先补测试并在重构前跑通，再重构。
