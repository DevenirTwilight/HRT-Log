# HRT Log — UI-05 任务书：视觉精修（吸收样图的好设计，保留现有功能）（2026-10-18）

> 交给 Claude Code 执行。负责人：DevenirTwilight。本任务书即本轮授权来源，开工时原文归档并写入 REQUIREMENTS（下一个 § 编号）。

## 0. 目标与原则

负责人对比了设计样图和当前应用，希望界面**更美观**：吸收样图在视觉上更好的部分，同时**保留应用里功能更完整的部分**。

本轮只做视觉和布局，不改功能：

- 所有按钮继续调用现有回调。
- 不新增写入路径。
- 不改任何计算（剂量、库存预测、时期投影、浓度）。

样图的设计语言，下面统称“样图风格”：

- **浅色底卡片里嵌白色列表**：卡片用 `surfaceContainerLow`，内嵌圆角 16dp 的白色（`surfaceContainerLowest`）列表；行与行之间用细分隔线。
- **可点的行有右箭头**（chevron），每行至少 56dp。
- **类型用彩色圆形图标区分**：不同类型的底色不同，但同时保留文字类型名，不能只靠颜色。
- **层级清楚**：每张卡只有一个主操作；标题加粗；次要信息用 `onSurfaceVariant` 小字。
- **胶囊标签**：状态和计数用小圆角胶囊（如“当前时期”“约 3 天后用完”）。

参考样图在负责人的私有画布上，执行环境无法访问，以本任务书的文字描述为准。

## 2. 改动清单（每节一个提交）

### A. 今天卡（`TodayCard.kt`）

采用样图风格：

- **进度**：“已服 x / y”从普通文字改为日期行右侧的半透明胶囊（`onPrimary` 16% 透明底）。
- **倒计时**：下一次服药时间旁显示“还有 n 小时 / n 分钟”（OVERDUE 时仍显示现有的“已过时间”，不显示倒计时）。只用 `slot.at` 与当前时间的差值做展示，不写入任何数据；每分钟刷新一次即可。
- **主按钮**：“现在服用”前加勾号图标，高度 52dp，白底、主色字。
- **⋮ 按钮**：改为 52dp 圆形描边按钮（`onPrimary` 50% 透明描边），与主按钮同一行同高。
- **分隔**：“下一次”区与下面的“同一时间 / 稍后 / 今天的记录 / 今天的预约”之间加一条 `onPrimary` 20% 透明的分隔线。
- **记录行**：每条前加 28dp 小圆形状态图标：已服为勾、漏服为 ✕、跳过为横线、未确认为问号。状态文字保留。

**保留应用现有**：同一时间、稍后、今天的记录、今天的预约四个分区，超过 3 条的折叠，以及简洁模式隐藏药名（UI-04 的全部行为）。

### B. 首页库存提醒（`TodayCard.kt` 中的 `HomeStockCard` 和 `CalendarScreen.kt` 的位置）

采用样图风格：

- **改成紧凑横条**：圆角 16dp，`tertiaryContainer` 底。左边库存图标，中间两行（粗体“[药名]快用完了”加小字“约 n 天后用完 / 已用完”），右边一个“添加库存”按钮（`tertiary` 底）。整行可点，点击进入库存页（保留现有“查看库存”的作用，不再单独放这个按钮）。
- **位置**：移到今天卡正下方、月历之前，让需要处理的事都集中在顶部。
- 多种药同时偏低时，每种一条横条，最多 3 条，其余用“还有 n 种 →”进入库存页。

**保留应用现有**：判定仍用 `StockForecast.isLow`，不改阈值；“添加库存”仍打开同一个 `AddStockDialog`。

原来那一整句说明（“按目前的服药计划……”）不在首页显示，库存页仍完整保留。

### C. 库存卡（`StockScreen.kt`）

采用样图风格：

- **药名下加一行小字**：途径 · 频率（如“口服 · 每天 2 次”），复用现有 `scheduleText` 等已有格式化函数，不新增计算。
- **大号余量旁加“约 n 天”**：取现有 forecast 已算出的天数，没有计划时不显示。
- 原来的长句说明改为 `bodySmall` 次要文字，放在进度条下方。

**保留应用现有**：
- 单一主按钮与 ⋮ 菜单；
- 低库存整卡变色加“约 n 天后用完”胶囊；
- 包装记录折叠和展开后的“管理包装”入口及其全部对话框；
- 主按钮文案“开新的一盒”不改。

### D. 治疗时间线（`LongitudinalScreen.kt`，只改展示层）

采用样图风格：

- **顶栏加 +**：“添加里程碑”“新建时期”两个大按钮移入顶栏 + 号，点开后的菜单含这两项，调用原回调。测试 tag 迁到菜单项上，并逐条说明。
- **时期卡头部**：“当前时期”改为胶囊标签；标题行合成“[起始日期] 至今 · 第 n 天”（历史时期显示“[起] – [止]”）；方案每种药一行，前面加小圆点。
- **事件列表**：同一时期的事件放进时期卡下方的白色内嵌列表，在视觉上归入该时期。每行包括：
  - 36dp 彩色圆形图标：沿用现有 Material 图标，按类型着色，化验、就诊、里程碑、阶段回顾、其他各用一种底色，明暗主题都要达到 3:1；
  - 两行文字：类型 · 名称 / 日期；
  - 右箭头。
- 未关联方案的事件区同样使用白色内嵌列表；标题保留现有文案。
- 即将发生的事件：使用虚线描边卡，与已发生的区分。

**保留应用现有**：筛选标签（含“其他”）、“第 n 天”、全部 `EventKind` 的图标与文字类型。**严禁**改动 `LongitudinalProjection`、`PeriodTimeline`、`TimelineEdits` 等投影或编辑逻辑。“归入时期卡”只是渲染位置，事件归属仍完全来自现有投影结果；`PeriodStabilityTest` 是交付门槛。

### E. 抽屉（`AppShell.kt`）

**整体保留应用现有**（分组、名称、图标、“HRT 日志”应用名都不改）。只加一项：

- 库存入口在有低库存药物时显示数字角标（tertiaryContainer 胶囊），数字等于首页横条的数量，判定同 B。角标要有语义描述（如“库存：1 种即将用完”）。

### F. 医疗档案首页（`MedicalRecordsScreen.kt`）

采用样图风格：

- **“记录已发生的就诊”**：从全宽按钮移到顶栏 + 号，`contentDescription` 用原文案，测试 tag `medical-add` 跟随。
- **下次就诊卡**：
  - 左侧日期小方块：月 / 日 / 星期，白底，圆角 14dp；
  - 右侧：“下次就诊 · n 天后”小字，类型（粗体），时间 · 医生 · 地点；
  - 下方白色内嵌列表两行：“想问的问题 · n 条”“就诊资料包”。两行都打开现有复诊详情，取代原来的单个按钮。问题数量来自现有数据；资料包状态如果现有数据能直接读到（已生成 / 未生成）就显示，读不到就不显示状态，不新增查询。
- **已确认的就诊**：从每次一张大卡，改为按年份分组的白色内嵌列表。每行包括 40dp 类型圆形图标、类型（粗体）、日期 · 医生或机构、“有备注 · 问题 n”小字和右箭头。点击行为不变。

**保留应用现有**：“去过了吗？”卡（只把内容对齐成同样的圆角和间距）、“相关资料”、底部回收站、时区显示规则，以及“日期接近不是关联”（§87）。

### G. 全局细节（只在本轮改动过的文件中做）

- **分区标题**：统一为 15sp 粗体加次要说明小字，卡片圆角 24、内嵌列表 16、胶囊 10，使用 UI-02A 的 Spacing / 形状 token。
- **数字**：数字统一使用等宽数字（`fontFeatureSettings = "tnum"`），让时间和余量对齐。
- **对比度**：新加的彩色图标底色和胶囊，在标准、中、高对比度和明暗主题下都要达到 WCAG AA（文字 4.5:1，图标 3:1）。
