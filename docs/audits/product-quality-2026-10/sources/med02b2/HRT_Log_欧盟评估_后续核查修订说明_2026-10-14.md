## 1. 已在后续讨论中提出的修订

| 原稿的断言或建议 | 后续修订的正确处理方式 | MED-02B2 当前行动 |
|---|---|---|
| “没有 INTERNET 权限，因此技术上无法发送任何数据” | 无 INTERNET 权限限制应用自身的网络能力；但 Android SAF 文件提供者可以来自云端，用户主动选择导出/共享目标时仍可能使外部副本离开设备。不能作绝对保证。 | 记录数据流，区分应用主动通信、SAF/第三方提供者、明文导出、加密备份与外部副本；起草有代码依据的隐私声明。 |
| “GDPR 名义适用、义务近零” | 本地个人用途与应用开发者提供联网服务等不同场景必须分别判断。不能用一句话覆盖全部角色、场景。 | 列出数据处理者、外部提供者、是否服务端接触数据；标记需法律复核，不打分宣称“9/10 合规”。 |
| “不属于医疗器械” | MDR 取决于产品客观功能与制造者预期用途、宣传和文档。添加免责声明本身不会自动改变分类；M2 条件估计不能包装为个人临床测量/剂量决策。 | 统一拟议用途声明；建立会导致 MDR 重新评估的功能变化闸门。不自我颁发 Class IIa 或豁免结论。 |
| “GPSR / CRA 均不适用，捐赠不与产品挂钩就必然豁免” | GPSR/CRA 的适用性和商业活动/货币化判定应分别分析；不能仅按是否收费、是否捐赠一刀切。CRA 不同条款生效时间与主体范围不同。 | 分开列适用条件、未决事实、官方来源及重新评估触发器，不给出未经证实的普遍豁免。 |
| “EAA 边缘适用，健康 App 自动受影响” | EAA 有列举的产品与服务范围，不能把所有医疗/健康 App 等同法定覆盖。无障碍是独立且高优先的工程质量要求。 | 按 EN 301 549 / Android TalkBack 进行全流程审查规划，区分自愿质量目标与确定的法定义务。 |
| “纯软件不在 GPSR”或“GPSR 显然不适用” | 欧盟委员会的 GPSR 指引讨论软件与独立应用，不能仅因产品为软件而排除；还要分析经济活动和具体范围。 | 核对欧盟委员会最新 GPSR 指引，不直接宣布适用或豁免。 |
| “FHIR/EHDS 互通或法国 HDS 一接入就自动全部认证” | FHIR 数据导入导出、宣传 EHR 互通、代管健康数据和医院系统对接是不同事实；EHDS/HDS/CI-SIS 等具体义务需要场景化审查。 | MED02 V2 可参考 FHIR 语义，不增加云端/医院接口，也不宣传官方互通认证。 |
| “Git 历史版权风险极低，可直接结案” | 当前生产源码独立重写不能回溯授权公开历史、旧版本、标签或构建物；处理方案需审查实际公开可访问性、权利状态与分发范围。 | 不重写历史或擅删 Release；建立专门法律/许可审计任务和明确的决策记录。 |
| “F-Droid 必须字节级可复现” | 需核查 F-Droid 现行收录/构建与 reproducible builds 的准确要求；与原正式签名覆盖升级的兼容性尤其重要。 | 暂不申请上架；核查签名与独立源码构建路径，不擅自更换签名密钥。 |
| “现状评分 9/10”等 | 缺少可重复的评分标准、第三方认证与完整实测。 | 改为逐控制项 PASS / PARTIAL / UNKNOWN / NOT_APPLICABLE（附条件、证据与复核日期）。 |

## 2. 应保留并优先落实的工程建议

1. 根目录 `PRIVACY.md` 和四语应用内入口：逐条对应真实代码和权限；说明导出、备份、卸载、伪装边界与附件状态；先提案，具体 UI 修改另起独立 PR。
2. 统一预期用途声明及 MDR 功能变更审查：不自动诊断、不调整剂量、不把群体 M2 估算称为用户实际血药浓度。
3. 版本来源治理：区分公开 Release、已签名私人交付、默认分支及 stacked PR；尤其 B1 Room10 不是已安装到用户手机。
4. 全应用无障碍审查：EN 301 549 对照，四语、320dp、两倍字体、TalkBack、锁定/备份/异常和医疗附件未来流程。
5. 法规适用性记录和版权/分发专项：以最新官方文本及实际功能和商业模式为准，存在未知事实就标记待核实。

## 3. 与 MED-02B2 的工作边界

当前 B2-GATE 允许做事实审计、设计、官方文献比对、合成测试、兼容性/安全评估与明确分阶段 PR 计划；**不等于批准**上线医疗原件、改变正式文件密钥/加密协议、改 PNBAK1 密码学、合并 #27–#29、签名交付或申请商店分发。

医疗原件管理应在数据层区分文档格式、来源声明、机构、临床事件日期、签发日期、导入时间、分类、用户确认的链接和不可变版本；用户录入来源**不自动构成机构证明**。未经真实完整备份与跨设备恢复验收，不允许把附件功能开放为用户唯一原件的依赖。
