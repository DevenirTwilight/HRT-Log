# 80 · MED-04 文件信息 + MED-05 缩略图与文件查看器

日期：2026-10-29。需求：REQUIREMENTS §164（MED-04）、§165（MED-05）。分支 `feature/med04-file-category-20261029`（PR #150）、`feature/med05-thumbnails-viewer-20261029`。负责人要求原话见两节开头。样图 06/07 作基线，实现以负责人决定为准。

## 1. 结论

- **MED-04**：类别、文件日期、机构由用户自己填；填了就按样图 06 显示（「按类别」方块带数量、每行「类别 · 日期 · 机构」、「待整理」= 没填类别或日期）。没填就不画、不猜。
- **MED-05**：文件库每一行和文件页自动显示第一页缩略图；查看器能逐页浏览、缩放、平移；手机照片不再因超过 2048 像素而打不开。
- 使用 Android 系统自带的 `PdfRenderer`（内置开源 pdfium），没有打包第三方 PDF 库（理由见 §165）。

## 2. MED-04 设计

| 项 | 做法 |
| --- | --- |
| 存储 | Room 23 新表 `attachment_document_detail`（store+document 唯一、自己的修订号、更新时间）；不改 `attachment_document`、journal、link 与既有触发器；迁移只新增表与索引 |
| 校验 | 触发器 `guard_medical_file_detail_*`：类别在六种内、日期是真实日历日（含月末检查）、机构 1–80 字且非空白；修订号只能 +1；不能删除（清空用更新） |
| 操作 | `details()`、`saveDetail()`：按详情自己的修订号比较并写入；回收站里的文件不可改；不改原件修订号 |
| 备份 | 只有文件带信息时清单升到版本 3（`detail` 对象）；其余清单字节不变；旧阅读器在暴露数据前拒绝版本 3；候选库校验（`rc_document`）与恢复都带详情；恢复到新设备的文件没有导入回执，则不显示「导入于」 |
| 界面 | 导入第二步与详情页「编辑文件信息」；日期用现有日期选择器（窄屏用校验过的输入）；类别再点一次清除；机构限 80 字、去控制字符 |
| 读取失败 | 详情读不到时文件列表照常显示，类别与日期不画，并提示；不会因此改写 |

## 3. MED-05 设计与安全

- **缩略图**（`FileThumbnails`）：只在内存；最多 48 张；每次只做一个文件；沿用已认证、可撤权的读取器；做出的是独立副本，读取器自己的位图立即释放；锁屏、伪装、切换数据、离开页面、关闭都会清空并丢弃正在生成的结果；坏文件只标记自己，不影响列表，也不自动重试。
- **绘制安全**（`GuardedBitmap`）：在主线程绘制时检查位图是否已回收，回收也在主线程做，所以不会画到已回收的位图。
- **查看器**：`pageCount()`（上限 2000）、`pdfPageFit()`（任意页面缩放到最长边 ≤ 1600，高瘦的页面不再因尺寸被拒）；换页时新页先做出来再替换，旧页延迟 300 ms 释放；同时最多持有两页；换页失败保留当前页并说明；撤权或关闭时丢弃进行中的页。缩放 1–5 倍（双指、双击、按钮），放大后拖动平移，正常大小时左右滑动翻页；每个手势都有按钮（无障碍）。
- **有意放宽的一处（须复核）**：图片超过 2048 像素时，原来整体拒绝；现在按 2 的幂次缩小解码（源图边长上限 16384、总像素上限 1 亿），解码后仍受 16 MiB 限制。原因：手机拍的处方照片通常 3000–4000 像素，原来根本看不了。原生测试 `ProductionViewerSafetyAndroidTest` 中「2049×1 被拒」改为「16385×1 被拒」，并新增大图缩小与多页 PDF 测试。

## 6. NOT_RUN / 已知限制

- 真机与人工 TalkBack 未做；设备测试只能在 CI 看结果，本地未运行。
- 真实 PDF 的缩略图/翻页在本地只有 Robolectric 假读取器验证；真实 pdfium 渲染由 CI 的设备测试覆盖。
- Android 8：PDF 仍不能预览（系统缺陷，见 §165），图片可以；文件页写明原因。
- 很多文件时缩略图会逐个生成，首次进入页面可能先看到类型图标再换成缩略图；未测大批量（上百份）性能。
- 缩放后位图分辨率上限 1600 像素，放大到 5 倍时文字会变软（不重新渲染）。
- 没有的东西：上次备份日期、医生/机构管理页、从文件内容识别类别/日期（按 §164 不做）。

## 用户反馈修复候选 — 2026-10-29

### 名称

正式入口：医疗档案→医疗文件→文件详情→编辑文件信息（名称、类别、日期、机构）。名称预填真实document.title，不重新导入/加密；title和Detail在Room23现有表一次事务双revision CAS，失败原子回滚、取消不写、撤权拒绝。UNKNOWN保留中性op/doc，只读核对当前状态，不能归属历史COMMIT或自动重放；旧worker及旧列表回调都有窄竞态回归。完整备份使用已有manifest当前标题，不更改任何备份格式。原生测试扩展原五成员/多关联/独立恢复路径，证明一个原件与链接/UUID/封装/journal不变、旧import可核对，恢复后新名称保留。

### 阅读

正式“全屏查看”现在是独立阅读窗口，不含详情的机构/关系卡片或固定高度圆角框；fit读取区居中、保持比例，顶部标题返回与底部页码/翻页/缩放控件在必要安全边距内，单击显隐工具栏。Pinch/double tap/zoom pan复用现有认证Controller和GuardedBitmap；手势以局部值累计，不依赖逐事件已重组；仅main线程发布状态，未改位图分配、解析/内存上限或撤权流程。
