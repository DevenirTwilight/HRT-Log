# 身心状态重设计：验证与已知边界

依据 `REQUIREMENTS.md` 15 / 15a / 15b，设计已获审核。本轮只提交源码，不发布版本，也不修改浓度模型。

## 自动验证

- `WellbeingMigrationTest`：Room 1→2 迁移、由 0.2.0 生成的合成 v1 加密备份恢复、两条路径一致、未来备份拒绝；保留历史分数、备注、库存账本、化验等。
- `WellbeingRecordsTest`：回顾/症状/效果开关加密备份往返，排序保留分数，非法回顾不覆盖已有数据。
- `SymptomCatalogTest`：产品/途径/酯型明确匹配、缺失酯型不猜测、共有症状合并、立即分组仅取原话、地区规则、不添加急救电话、第三方转载及完整译文覆盖。
- `WellbeingUiTest`：未操作滑块不写入、选择后清除、DAY_* 标签、无平均分、螺内酯不添加症状、隐藏效果保留已有值且选填字段保持空。
- `WellbeingSummaryTest` / `ExportTest`：摘要日期边界、隐藏历史仍导出、CSV 六个文件与转义。
- API 35 instrumentation：原生 SQLite 迁移后安装约束；SQLCipher 新数据及包装来源/批号备份恢复和重开；阶段体重不写入当前浓度体重；原生滑块和长篇多语 PDF 分页。既有伪装会话、路由、返回和强制进程重启测试继续运行。

## 真机复核方法

在测试设备安装从当前源码构建的版本，使用合成记录：

1. 打开“身心状态”：三个标签可切换，每日四项初始“未记录”。记录/清除一项并返回页面，核对历史折线；管理里开关、排序、添加自定义条目。
2. 在升级前建立包含分数与备注的旧库/旧备份，升级或恢复后核对 DAY_* 合并、以前条目及全部历史内容。
3. 添加已明确分子/途径/酯型的药物，核对症状合并、出处、立即措辞、非官方译文及舌下说明。未明确酯型时不能匹配另一产品；停用药物后其专属条目退出当前列表。
4. 切换界面语言而保持地区不变，再切换地区而保持语言不变。症状来源集合不因地区减少；法国的监测规定和上报渠道只按地区显示。螺内酯症状显示“官方来源未列出”。
5. 新建/编辑/删除阶段回顾，全部选填字段初始为空；隐藏已有效果再编辑保存，旧值仍可导出。记录血压和阶段体重后核对浓度页当前体重未被修改。
6. 添加多个库存包装，逐个编辑来源/批号。核对库存数量、已用量及账本不因编辑这些文字变化。
7. 选日期范围导出复诊摘要，经系统文件选择器返回后可继续使用。打开 PDF 核对日期边界、长篇文字分页、化验原值/参考范围、症状来源、回顾全文及每日记录天数/折线；重启后数据保留。
8. 在简中、繁中、英、法及系统大字体下检查布局、滚动、TalkBack 滑块标签和文件选择器返回。

## 已知边界

- 本机没有可用 Android 模拟器；原生验证在 GitHub Actions 的 API 35 模拟器完成。尚未核对各 OEM 真机、大字体和屏幕阅读器的实际表现。
- 非官方译文与原话并列，原话为准；未核实的产品不添加症状。来源链接通过外部浏览器打开，应用本身没有联网权限。
- 症状记录保存组 ID、日期和备注，未保存当时每一种药物/来源的快照。摘要注明当前目录对应的来源，不能据此断言当时使用了某种药。将来更新目录时应保留旧 ID，并考虑保存来源版本。
- 每日曲线与浓度曲线同一时间轴的叠加按设计留待后续，本轮只保留可按日期/条目查询的数据结构。
