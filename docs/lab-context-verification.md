# Lab Context 合成验证步骤

2026-10-07，schema5/build10，仅full。此清单用于合成数据，不要求上传真实健康记录。

1. 升级前导出加密备份，覆盖安装沿用正式签名。旧化验结果保留，但上下文不自动补写；卡片应显示“未保存”。
2. 创建两个成分的合成实际记录和一个化验样本。展开采样上下文：各成分分别列最近实际事件；样本之后和已删除事件不得出现。没有历史快照的导入须保持未知，不从当前药物补猜。
3. 手动重建旧化验：显示实际生成时间与“根据现存记录重建”，不是声称采样当时已经保存。版本候选框应能查看前版。
4. 修改结果数值/备注：上下文版本不增加。修改采样时间/时区/项目：新增版本，旧版仍显示旧采样字段。明确勾选估算或点击重建也生成新版本。
5. 修改历史实际记录或药物配置：已保存上下文保持原值；明确重建后最新版才使用修正后的记录。并列同成分、同时间的实际记录全部列出。
6. 48小时仅是产品回顾窗口。已记录迟服、确认漏服、自动未登记分别计数；不把未登记判定为漏服，不根据结果判断正常或因果。
7. 可选估算默认不勾选。勾选后只使用采样前180天范围内实际记录、既有当前体重设置和现有模型；不使用计划、不使用任何化验拟合。来源、缺项、未支持与模型局限仍显示。结果/参数快照不是完整旧版本引擎重执行系统。
8. CSV ZIP含lab_contexts.csv全部修订；主PDF含每次化验最新上下文，不能用另一成分的服药时间填“距服药”。加密备份恢复后版本和原JSON保持一致；删除化验同时删除其上下文。

自动覆盖：LabContextTest（多成分/未知/边界/不覆写/兼容/非法恢复回滚）、LabEstimateTest（舌下正值/排除未来/不自校准/缺失输入/非法单位/备份往返）、LabContextUiTest（版本切换/重建确认及合成截图）、ExportTest（CSV全部修订文件）；API35原生MigrationBaselineTest含1→5/3→5/4→5，WellbeingAndroidTest用原生PDF分页加入上下文。

实际执行结论见HANDOFF 2q。OEM、字体放大、TalkBack和用户真实覆盖安装结果仍需在设备上确认；不得把合成CI称为用户数据已验证。
