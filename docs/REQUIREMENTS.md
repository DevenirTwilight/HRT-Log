# HRT Log：需求说明（接手必读）

本文件汇总产品负责人（下称"用户"）给出的全部要求：原始规格、后续追加的指令和中途改动的决定。冲突时以**后面的决定**为准，第 3 节列出了所有改动。工作进度见 `docs/HANDOFF.md`，原始设计计划见 `docs/PLAN.md`，许可状态见 `docs/licensing.md`。

## 1. 产品

- 名称：**HRT Log**（中文：HRT 日志）。用途：跨性别 HRT 的用药提醒、服药记录、库存、身心状态、化验和血药浓度估算。
- 目标用户：在法国的用户（参照 HAS 2025 年 7 月建议），以及中国大陆和海外的华人跨性别群体。
- 包名：`net.plainnotes.app`（用户选定；包名、类名、通知渠道 ID、文件名都不得出现 hrt、trans、hormone 等字样）。
- 平台：原生 Android，Kotlin + Jetpack Compose + Material 3，minSdk 26，target 最新稳定版。
- 数据：Room + SQLCipher 加密；无账号、**不申请 INTERNET 权限**、不接入任何分析或统计 SDK。
- 架构：MVVM + Repository + Hilt；浓度引擎是纯 Kotlin 模块 `:pk-engine`。
- 语言：英文、简体中文、繁体中文、法语（法国）。所有文字放进 strings.xml；新增文字必须四种语言齐全（有 `TranslationsTest` 检查）。
- 构建变体：`full`（GitHub / F-Droid，含伪装模式）和 `play`（去掉伪装模式）。

## 2. 硬性规则（必须遵守）

1. **真实健康数据**：`reference/transmemo.db`，以及用户上传的 Trans Memo 数据库和 HRT tracker 导出文件，只能在本地用于测试导入器。不得提交到仓库，不得出现在测试数据、截图、文档或提交信息里。测试一律用合成数据。
2. **Trans Memo 是闭源软件**：不得反编译，不得复制它的代码、文案、图标、配色或插画。界面必须原创。唯一例外是读取用户自己导出的数据库来做导入器。
3. **剂量**：应用绝不给出剂量建议，不出现"应该加量/减量"，不显示推荐剂量、剂量范围或"不推荐""超出建议"之类的评判，不预设用药方案模板（"每天一次 / 早晚各一次"这类快速填写只填频率和时间，剂量由用户自己填）。漏服只显示"已漏服"，不建议补服或加倍。
4. **浓度估算的说明**：曲线是基于群体参数的估算，个体差异很大，不能替代抽血化验。首次进入和模拟页上都要写明；抗雄药物的血药浓度不等于抗雄效果。
5. **不猜测**：导入时遇到无法确定的字段、编码或单位，一律不猜，让用户确认。
6. **药物评判**：不得对某种药物另加警告或贬低（例如不因 HAS 把 CPA 列为二线就在界面上贬低它）。
7. **Git 与协作**：只在分支 `claude/new-session-1959qb` 上开发；除非用户明确要求，不创建 PR；提交信息、代码和文档里不写 AI 模型名称。
8. **许可**：在 `docs/licensing.md` 记录的授权明确之前，不发布任何包含现有浓度模型的公开版本（GitHub Release、F-Droid）。

## 3. 原始规格之后的决定（按时间顺序）

1. 包名由暂定的 `net.quietledger.app` 改为 **`net.plainnotes.app`**。
2. 体重只用于浓度估算，不保留体重历史。CPA、比卡鲁胺只在引擎里支持。凝胶和贴片的必填参数要么由用户填写，要么使用公开说明过的默认值。高可靠提醒是可选项，默认关闭。
3. 界面曾被用户认为太简陋，之后整体重做（原创的青绿 / 珊瑚配色）。
4. **"方案 A"**：把 Transmtf HRT Tracker（MIT）的浓度引擎和化验校准移植成 Kotlin，界面原生实现；"校准也搬"。这与原始规格第 1 节"浓度引擎必须独立实现"冲突，许可问题见 `docs/licensing.md`。用户后来要求同时做第 6 节的文献调研（M4a）。
5. 语言：法语使用"法语（法国）"等带地区的语言标签；不需要的地区选择不显示；新增繁体中文；数字按语言地区显示小数点。
6. 历史页仿照 HRT tracker 的样式：按天分组的卡片、给药途径图标、"剂量 2 mg（1.53 mg E2）"、时间标签。另加"批量补录"：选药物、起止日期、每天的时间和剂量，只补过去的时间，不扣库存。
7. 新建药物时提供"每天一次 / 早晚各一次"快速填写（只填频率和时间）。
8. 新增**从 HRT tracker 导入** JSON 导出文件：完全重复的记录必须让用户选择"合并"或"全部保留"；不支持的内容计数后跳过。
9. 日历改为真正的日历：日 / 周 / 月 / 年四种视图；已服、部分漏服、已漏服、计划服药的格子颜色不同；日历下方显示库存预计（哪天用完）。
10. 对比度三档的名称、"下滑两次退出"不用按规格改；伪装模式的便签外壳保持"搜索密码进入"。

### 4.3 浓度模型：M4a 文献调研（不改现有模型代码）
- 产出 `docs/pk-model.md` 和带出处的 `pk-engine/src/main/resources/pk-params.json`，覆盖：戊酸雌二醇口服、17β-雌二醇口服、透皮凝胶、贴片、醋酸环丙孕酮、戊酸雌二醇肌注、舌下雌二醇、螺内酯（含坎利酮）、口服微粒化孕酮。
- 每个参数写明数值、单位、出处（作者、年份、DOI 或说明书链接）、研究人群和局限；**没有可靠来源的不填**。
