# 量纲与错误合同 v1（实现前冻结）

算法 `ansm03-exact-v1`；纯函数，无IO/时钟/随机/数据库/PK；同输入、冻结来源和版本输出相同。

量 = 精确十进制 + 单位 + 语义身份。质量单位µg/mg/g可按10的幂换算；mL是体积，
TABLET/CAPSULE/PATCH/PUMP是不同计数维度；µg/24h是独立释放速率维度。
语义身份分 ACTIVE_MASS（完整成分标识，含盐/酯/水合物/角色/组）、FORMULATION、
USE_COUNT、RELEASE_RATE、ABSORBED_MASS。相同mg的制剂与有效成分不可相加，吸收量不从给药量推导。
未知身份/规格不等于零，不从药名或PK配置恢复。SA/FT/ST保留不同身份，不能相加。

数字输入ASCII十进制，不接Double，不接受NaN/Infinity/指数/地区逗号。输入长度≤80、小数≤18、
数值≤10^18；输出同限额；整数中间运算BigDecimal精确完成，无MathContext舍入。
非终止除法/超出刻度返回PRECISION_OR_RANGE，不四舍五入；1/2、1/4等精确表示，1/3拒绝。
零允许表示耗尽/质量数学；实际使用输入必须>0，负数始终拒绝。无库存容差EPS。

加减要求完整语义身份相同且单位维度兼容，结果不负；不同商品同成分强度不自动合并。
跨语义转换必须走显式有向关系（每片含量、每泵制剂量、浓度等），来源包含文档/段落、
核实日、源版本、摘要哈希、产品/包装/快照身份；仅合成来源用于原型测试。
每次转换还要求用户实际包装确认与同一冻结snapshot/version吻合；知道mg/片不证明来自该包装。
不自动反转关系：反向关系必须另外明确声明和审核。分数片计数本身不证明有效成分均一性；
若关系涉及片数且量为分数，只有额外核实的分片依据允许换成mg，否则FRACTION_NOT_VERIFIED。
多成分关系一项一项选定语义，不自动求和，不实现盐/酯摩尔质量换算，不以总载药量/天数推释放速率。

包装快照分别保存：名义总量、名义使用次数、每用制剂量、各成分每用量、释放速率、
明确确认的可用容量（可空）及冻结来源。名义容量不等于实际可用量；灌泵/残余未知不能创造库存。
只允许在已经确认、身份/单位兼容的数量上计算剩余；旧容器无快照时失败，不从当前目录补。

结果为Success（量、算法版本、使用的来源快照）或Failure（稳定原因枚举），不用nullable Double。
错误优先序：数值/类型非法→历史快照缺失→来源不足→包装不匹配→来源版本不一致→
规格不明确→成分不一致→单位不兼容→分片未核实→精度/范围不足；以实现分支逐项测试为准。
补充并发/操作协议错误包括重复操作载荷冲突、VOIDED、库存不足；不作为生产接线实现。
失败没有写入/提醒副作用。默认不进行任何网络访问、推荐剂量、实际途径/计划/PK修改。

## 先行负向证据

LegacyBoundaryTest只建立旧capacity/used标量的合成投影：不同强度/单位/可用性拥有同一投影，
不存在能唯一恢复其包装身份的函数；0.1重复Double减法无法得到精确0。
这些测试预期PASS，证明信息不足，不故意使生产测试失败。新核心随后以结构化拒绝覆盖对应输入。

## 实现审查补充（2026-10-16）

- 部分泵压、胶囊和贴片也不假定成分按比例均匀，分数计数→含量与逆方向同样需要额外依据。
- 零值数学与正数实际使用分开（actualUse）；verifyDeclaredContent只比较两项明确事实，
  不一致返回DECLARED_QUANTITY_CONFLICT，保留用户原值，不替用户选剂量。
- 释放速率/吸收量不参与ContentRelation，化合物到另一化合物的质量关系也不接受；没有分子量/药代换算。
- 单位常数采用精确SI十进制关系，是算法合同的一部分；包装关系另需来源和实际包装确认。
- 多错误同时存在时按各公开函数的明确分支优先；加减先校验数值/类型、维度，再检查身份。
  跨内容转换先数值、快照、来源、包装、版本、关系规格，再检查支持的语义、身份/单位、分片和精度。
  Snapshot查不到有向关系返回来源不足，重复关系返回规格不明确，不做隐式逆查找。
- 合成来源的digest是虚构占位值，不是官方校验和。verified输入不能替代未来来源审阅器。
- PresentationSnapshot拷贝关系列表；Quantity/Meaning/Ref/Relation只读。更新构造新快照，旧捕获不变。
