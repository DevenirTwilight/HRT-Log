## 5. ANSM-04｜官方文档入口、可追溯安全资料（实际用户功能）

**目标**：正式 App 内用户可理解某药的可靠信息从何而来，查看经核实的 RCP/Notice 入口；在权利与字段验证允许时读取可追溯的辅料、储存、禁忌和相互作用等**原文事实**。不要把“入口存在”当“正文已核实”。

### 5.1 数据分层和许可门

- `CIS` = 官方产品身份；`CIP13` = 包装身份，需检查 CIP→CIS 所属；同名不同 CIS 不合并。
- RCP（Résumé des caractéristiques du produit）与 Notice（患者说明书）是**两种独立文档**；BDPM 的页面标签、面板 ID/URL、HTTP200、正文内容、正文版本、内容实核日期要分别记录。
- `AUTHORIZATION`、`MARKETING`、`SUPPLY` 与 `DOCUMENT_VERIFICATION` 是不同状态；上市许可有效≠本地有货；无断供公告≠已证实可供货。
- 产品名、成分角色 `SA`、`FT/ST` 冲突、分母、规格、剂型、所有给药途径保留原文；不能把 FT 无证据标准化为 ST 或把功能性成分和活性成分相加。
- 许可证据：继续解决 BDPM 下载页标示 Etalab Licence Ouverte v2.0 与其链接 PDF 显示 v1.0 的冲突，另核对 RCP/Notice 全文再利用的实际权利范围。只记录可核实结论，不能因为出现“政府官网”便推定全文可任意再分发。
- 许可/内容未核实前：**正式 APK 官方数据打包保持 OFF**；可开发通用 DTO/离线读取器/只读页，演示只用合成标识或明确标记用户自填资料，不将它伪称官方认证。

### 5.2 只读数据模型与 UI

设计最小的 `DocumentReference`/`DocumentEvidence`/`SourceAttribution` 结构：documentKind、CIS/CIP、sourceNamespace、sourceURL、retrievedAt、pageIdentityVerifiedAt、contentVerifiedAt、textReuseAllowed/unknown、documentVersion/lastModifiedIfVerified、evidenceDigest 与 fieldEvidence；日期不明就是未知。证据是可审计快照，不以联网成功/文件存在来替代正文校验。

在正式药物详情展示：来源身份/更新时间与核实日期、RCP/Notice 两个独立明确标签；文档内容未知时提示“官方页面入口已核实／说明书正文尚未核实”。只有用户显式点击、且 HTTPS URL 主机和路径从可信白名单验证后才调用外部浏览器；不得在 URL 中传药物日志、记录 UUID、个人输入、查询或令牌。App 保持 No INTERNET。

若明确许可并经字段级核实，按内容/法律支持范围提供可追溯的禁忌、警告、相互作用、辅料、储存和有效期**原始产品信息的受限展示**：每条字段可追溯至具体 RCP/Notice 节、版本、核实日期；不把不同产品的原文合并为统一治疗建议。不经授权不抓全文缓存/离线嵌入；合法而未核实的正文也不展示为“已验证”。

必须支持未知、撤销/停产、旧版本、资料下架、损坏、无网络浏览器、非法 URL、无合法来源、四语 UI、可访问性与手动路径。历史关联查看冻结参考，不随着目录升级改变旧实际用药/库存。设计 RCP/Notice 仅资料入口而非医学推荐入口；提示咨询医生/药师不代替处方。

### 5.3 ANSM-04 验收

正负样例验证真实 URL allowlist、RCP/Notice 不串用、只有页面证据时正文状态仍 UNVERIFIED、源版本更改后历史不漂移、中文/法文药名原文、CIP 与 CIS 所属、无合规许可时 release 无官方正文/数据；Android 浏览器 Intent 不带健康参数、锁/伪装阻断、备份/恢复不复制不获权内容。全部六 CI；真机浏览器/人工 TalkBack 未执行记 NOT_RUN。

按至少 2 个 PR 拆：`ANSM-04A`（文档证据/DTO/安全外链/只读正式 UI）与条件化 `ANSM-04B`（经过合法性和字段核实的文本/来源快照）。04B 条件不满足仍可交付 04A；不以复制说明书全文换取进度。

## 6. ANSM-05｜药品特定安全教育信息与事实累计（高风险、受门控）

**目标**：在可靠、可追溯的资料范围内给用户展示药物安全、注意事项和监测资料，避免产品给出个人处方或假确定性。这一阶段不是自动诊断或临床决策支持，不因开发任务书而免除科学、法规和适用用途审查。

### 6.1 分层实现

- **05A 低风险只读资料**：在 ANSM-04 的有来源字段上按产品/成分/途径展示适用的说明书警告、常见注意事项、医学检查信息入口与“最后核实日期”；对应来源必须和产品身份/国家/版本一致，不可从论坛、臆测或别的国家说明书当法国官方内容。
- **05B CPA 累积记录（仅事实统计）**：如果符合项目需求且统计输入/单位/来源已获认可，可展示用户已记录的醋酸环丙孕酮（CPA）**历史累计给药量**，以同一有效成分身份、已确认单位和原始记录/更正快照累加；去重，排除 VOIDED/已撤销、识别补录未知和未覆盖时段。旧记录没有足够身份或换算依据时标记部分/未知；**不设置“安全剂量”“安全累计阈值”“你的风险低/高”的断言或颜色分级**。不得将 CPA 基团/其他盐酯错算，也不利用换算不足的记录补零。

### 6.2 医学与法规硬门

- 显式预期用途为个人离线记录与官方资料查阅；不得暗示个性化治疗决策。任何新增“你的风险”“推荐调整剂量”“漏服补服”“安全区间/阈值”均为新医疗功能，须独立产品、科学/法规/临床审查，默认 NOT_IMPLEMENTED。
- 每条医学表述有具体来源、发表/更新或检索日期、产品/国家/途径适用边界、译文/人工核实状态。不同意见/不完整证据直接呈现不确定性；官方更新后旧快照仍可追溯。
- 四语不能把“不适用/未知/资料过期”翻译为“安全”；无未经授权的临床原文大段复制。
- 不以研究模型预测血药浓度解释真实患者风险；不触碰 PK 参数和 PDF。

### 16.2 多源时间不可混成一个“当前状态”

字段包含：`dataset_kind`、`source_displayed_update_date`、`individual_file_update_date`、`retrieved_at_utc`、`dynamic_generated_at_utc`（如有）、`source_content_digest`、`generator_version`、`catalog_revision`、`supersedes_revision`、`rights_status`、`next_review_due` 或显式无此保证、`field_verification`。没有原生发布时间的，不能用下载时间反填其发布时间。

测试人为制造：同一时刻获取的产品文件为9月版本、包装10月版本、供应文件另一天版本、动态重要信息当场生成；UI不能合成“所有数据更新于10月16日”。同版本重复生成逐字节一致；不按系统当前时间影响哈希；跨版本对照须列新增/消失CIS/CIP、状态及源字段变化，记录旧引用冻结。存在冲突不得自动选择“最新更安全”或“销售中”。

## 18. ANSM-05 药品安全资料：逐项覆盖并避免未核实风险结论

制定 `SAFETY-COVERAGE.md`：每项标明来源机构、具体CIS/成分/剂型/途径/适应证、发布日期/来源最后核实日、证据级别、临床核实状态、译文状态、是否可展示、UI入口与回归测试。来源从旧摘录迁移时必须重新核查，不得直接复制旧表格/剂量数值/建议。

| 事项 | 不得遗漏的审查对象 | 产品行为限制 |
|---|---|---|
| **CPA 与脑膜瘤** | ANSM/HAS/官方RCP最新的风险通告、适用对象/剂量/强度、官方文件/共签说明、MRI等监测资料；原摘录中3g/12g/36g及风险率表仅作待复核历史参考。来源可能按法规和时间变化 | 事实累计只表示**被完整记录、单位可确认的历史量**；不设“距安全阈值还有X”、自动提示“接近3g”等带风险判定的提醒；不自动生成MRI日程或停药建议。准确的官方说明可在完成审查后只读展示 |
| **螺内酯** | 高钾、肾功能、合用药相互作用及监测的具体原文/适用人群；旧摘录的复查时间必须重新核实 | 不从用户用药表/化验记录自动推断应做血检，不诊断高钾或替代医师 |

### 18.1 CPA事实累计的确定性数学规格（即使不上线也必须给出可测合同）

- 精确界定被统计的成分与商品身份；已核实CPA原始量以质量单位（mg，显示时可换g）表示，禁止把“片”“包”“配方成分总量”直接相加；盐酯转换没有可验证来源就无法加入。
- 仅汇总**真实已记录的用药事件**，以保留的原始给药事实和冻结快照为准，不把未来规则/计划生成的槽计入已服剂量；改期、跳过、取消、删除、恢复、修订、补录、重复导入需有单一事实判定，不能重复累加被冲销版本。
- 可选统计“所有记录可确定的CPA累计量”和“已记录但无法确知质量的条数/日期”；**不**声称它是患者终生完整累积暴露，尤其不能填补 App 开始使用前或历史缺口。部分总量始终明确 `PARTIAL`，不把未知当0。
- 历史量依记录发生时间与来源修订固定，不按今天品牌或商品数据库重新估算；给药日期与录入时间分开，时区/跨日变化有确定规则；必要时给出来源列表、所含事件数、排除原因。
- 若已确认同一记录确实包含多个CPA成分行，只依据有解释的成分角色和冻结实际质量计算一次，不把SA/FT重叠重复计算。
- 更正/导入/恢复前后数字稳定，跨数据库UUID作用域隔离；编写固定合成时间线、性质测试、边界数、未知比例以及四语误读测试。
- 不比较任何风险阈值、不绘制个人风险分层或累计“警报红线”；新增这样的个人化功能必须独立临床/产品审查。

### 18.2 文献和规定的地域与时点

不能把 2019、2024 或其他年份的官方文件直接写成 2026 年依旧完全相同的现行规定。对CPA年度说明、患者告知/复查政策、官方措辞及适用剂量，逐条审核当前主管机关材料；记录变更对照和法律/医护审查门。过去的医学/监管事实可以作为历史资料显示，但不得向用户说“当前必须如此”除非有最新有效证据。

## 19. 地区、来源与商品映射：用户手动药物永远不能被法国目录覆盖

模型和 UI 明确来源维度：`FR_BDPM_OFFICIAL`（真实官方并经许可确认）、`USER_ENTERED`、`OTHER_COUNTRY_UNVERIFIED`、`HISTORICAL_OR_IMPORTED`、`SYNTHETIC_DEBUG_ONLY`（严格限测试）。不要把用户国籍、SIM、GPS、手机语言或当前地理位置自动当成药物销售地区；允许用户**显式选择参考资料所属地区**，默认不强制更改已输入药物。

- 目前 ANSM-01 只有**法国选定范围**，不建立中国NMPA官方目录、不声称全球药品覆盖。中国、其他国家、进口商品仍可手动录入，来源未证实则明确USER_ENTERED；需要NMPA/其他国家真实资料属于另行核实的跨地区扩展，不应被悄然宣布完成。
- 中文/法文名、学名、别名检索要保留原语言和重音、法语ligature；用户编辑的名称不因匹配法国商品而自动重命名。`brandNames`旧静态提示不是官方同物/同剂量证据。
- 仅当同一可信namespace/CIS/CIP及实际来源匹配才能建立可引用官方身份；同成分不等于同盐/酯、剂型、规格或可互换治疗。禁止跨国家品牌自动等价、自动库存换算或建议改药。
- 法国官方授权/处方状态只描述**该地区该版本**，不能推断用户合法拥有此药、能在所在药店购得、可报销或适用于个人治疗。
- 历史进口/停售/未收录商品要保留原用户记录及可用库存旧路径，不强制用户更换药品。

至少测：在中文界面选择法国目录（仅启用时），法国UI手动录入外国产品、设备切换地区但旧记录来源不漂移、重音/别名查找、同成分不同酯不匹配、跨地区同品牌不同包装不匹配、无位置权限、不联网。

## 20. 离线官方来源更新、兼容历史、版本回滚与外链隐私

任何未来资料刷新都是**维护者在开发环境执行的受审核版本更新**，不是 App 后台抓取或运行时联网。建立专用确定性流水线：

1. 记录原始字节、下载URL/重定向、UTC、HTTP结果、页面显示日期、每文件独立更新日期和SHA；输入放合法位置，不提交无权公开的全文。动态重要信息单独生成时间与版本。
2. 严格解码/保留原文；对重复CIS/CIP、错误父CIS、错误类型、未知成分角色、状态冲突和明显字符串损坏整体拒绝或标记经审阅的UNKNOWN，不自动猜值。
3. 形成 `REVISION-DIFF`：本次新增/删去/变更条目、授权/销售/供应差异、RCP与Notice入口或内容变化、许可及再分发条件变化。更新不能自动修改用户现有药物引用、记录、容器已确认容量或旧库存消费。
4. 每个快照独立 manifest、catalog SHA、源行/页证据、生成器与测试版本；应可重复生产相同输出。旧版保留可追溯归档，不覆盖老证据（除非明确不再有权留存该原文并提供替代审计元信息）。
5. 法律/人工真实性门未通过就拒绝发布新数据；若旧版本过期/被撤销或法律适用发生变化，按显示策略标记 `STALE`、`UNVERIFIED` 或关闭官方数据展示，不能悄悄退回到此前未经确认的值。
6. 当前目录消失不使历史快照不可解释；新目录文件损坏时 App 仍可进入手动药物管理、查看旧记录，不崩溃、不自动清库；不把“哈希正确”视为信息仍然准确。
7. 提供用户可打开的“关于→数据来源/版本”信息：法国官方来源、具体数据子集/更新日、摘录/校验日、再利用署名/无背书、哪些字段未核实、是否离线快照、为何可能过期；尚未获许可时只显示真实的用户自填资料说明，不伪称内置BDPM。
8. 打开外部浏览器时说明会离开本地App，第三方浏览器/网站可知用户查看了哪个药品页面；只传可信固定公开产品文档URI，不加入用户资料或跟踪参数。后台/锁定/伪装恢复应避免把上次私密页面意外泄露在应用内；不新增INTERNET权限、analytics或后台刷新。

针对官方数据启用或移除，分别做 debug/unsigned Release 实际产物清单检查，不仅是 Kotlin 源码扫描；合成官方标识或测试目录不得残留到正式产品。发行日期、资料更新日期、文件独立更新日期、用户资料录入日期及给药日期是不同语义。

## 21. P4/P5 全局完整性的补充验收（不重复前文实现）

虽然V1覆盖了备份，仍须明确验证**全库完备性**而不是“逐容器成功”的总和。特别增加以下硬负例：

- 仅存在 `measured_operation` 而没有产生流水的失败/未知/重复/零量操作；消费失败必须留下**符合定义的事实**或完整回滚，不得生成半操作幽灵。
- 备份恢复时缺少跨两个包装的 REVERSE 第二份、额外无配对分配、多余 ledger、异容器反向引用、错误record revision、旧 dataset UUID、退役身份却错误绑定新整数ID、伪造源摘要与同数值不同量纲。
- 手工实盘之后补录历史消费、之后撤销消费、无差额实盘、观察与消费同墙上时钟时间戳、账本头指向未来/他包装、原余额恢复相同但票据过期（ABA）、不同用户会话重试。
- 物理精确数量与 legacy cache 表面一致但源断言不一致；不能靠“余额看上去对”放行。需逐笔验证原始输入、方向转换、单位、限定数值范围、实际确认、原始金额与逆集合。
- 先经可信隔离数据库整体审计，**原子提交前**才接受恢复；失败时目标库所有业务表/触发器/FK/数据集epoch/附件禁用元数据不变。新业务格式须被旧reader在写入前NewerBackup拒绝。
- 提醒与库存UI共用同一历史快照/预测版本，在数据UNKNOWN时既不宣称确定剩余日期也不自动发送“你缺药”的医学判断。重要：明确 `UNKNOWN_SOURCE`、`UNKNOWN_UNIT`、`UNKNOWN_CAPACITY`、`CONFLICTING_OBSERVATION` 与 `LEGACY_UNVERIFIED` 的不同提示。
- 真实记录修订时，**来源更正**绝不调用真实服药反向库存路径，**实际剂量/使用包装更正**只按冻结原消费逆操作；跨页面返回/双击/断网模拟均不产生双扣（App自身始终无需网络）。

## 22. ANSM-06 更新生命周期、药物警戒和批号核验

## 26. P4 新硬门：每个包装必须自描述库存编码，不能靠引用表猜测

继承 `docs/ansm-integration/p4/stock-encoding-version-contract.md`，将其加入 P4 当前最高优先级与 P4-B 备份验收。

### 26.1 根因与正式合同

旧 `ContainerEntity.capacity/used` 使用标量语义，而候选新模式在相同旧数值字段中用安全范围内的**整数刻度**表示精确物理库存。假如新引用/PRESENTATION/identity 表全部缺失，`capacity=56` 既可能是旧56个库存单位，也可能是新56个刻度；**不能从数值、名称、药物单位或整数形状证明语义**。

实施经审核的容器内生区分字段或语义等价方案，现有提案：

```sql
inventory_encoding TEXT NOT NULL DEFAULT 'LEGACY_SCALAR'
```

候选取值：`LEGACY_SCALAR` 与 `INTEGER_QUANTA_V1`。编码表示存储格式，不表示官方认证、临床用量或成分等效。旧库升级全部默认 legacy、保留原容量/已用值/流水；**仅显式新建且经用户确认的包装**允许新编码。不得通过旧 resize/修改或普通 UPDATE 将旧容器改成新编码；禁止将旧Double反向包装成丢失的真实精度。

### 26.2 约束与恢复

- 新编码容器必须具有同一当前 dataset 的唯一稳定容器 UUID、合法 PRESENTATION 和冻结来源；有 PRESENTATION 的活容器反向也必须对应新编码，缺一边即 `CORRUPT/UNKNOWN` **拒绝新模式写入与新备份恢复**，不可静默回退旧 Scalar。
- Tombstone/退休 UUID 不得以 `legacyIntegerId/original_handle` 和新复用的整数 ID 重新相连。新建旧模式容器仍可有稳定新身份，**稳定身份≠精确库存编码**。
- 如果候选 **Room11→12** 加列（不同于先前“45表定义不变”的旧检查点），需真实生成 Schema JSON 与整个 Room1…11 升级/失败回滚/旧 Room11 安全拒绝测试；正式版本号以最新主线未占用者为准。
- 候选 **PNBAK1 业务 Schema10→11** 应将该标记加入正式显式 writer/reader/白名单/预算/严格校验；旧 Schema1…10 缺标记视为 legacy，不能携带新模式表。新版11缺标记、坏类型、未知取值或引用对不上必须在**目标库退休/清除前**拒绝。
- 旧 reader 检测到新版头必须 `NewerBackup` 拒绝；错误把新格式标记为旧头、仍含新列或新表的伪装要拒绝，不许悄悄截断。对信息完全删掉且精心伪装成真实旧资料的恶意重写，不能冒称存在无法实现的密码学检测保证。
- 完整全库操作、零效果事实、跨包装逆集合及缓存核验通过后才可决定原子恢复/缓存重建。正式用户创建/消费入口继续 OFF，直到 P4 全部准入条件满足。

### 26.3 必需的真正能失败的测试

至少覆盖：旧库新迁移默认；无引用但有整数编码；有 PRESENTATION 但标记为 legacy；重复标记/非法类型；有消费的容器编码被修改；旧数据错读新整数；旧reader读取新库；旧头混装新表；新来源表被恶意删除；退役容器 ID 复用；新业务备份往返；失败注入目标库字节/逻辑指纹不变。API26/29/35 使用真实 SQLCipher，分别留源 SHA 与运行证据。

## 27. 导入器、CSV/PDF/Visit Pack 与数据可移植性（V2 缺少的下游功能闭环）

现有项目包含历史导入器（例如 HRT Tracker/Trans Memo），普通 CSV/PDF 与 Visit Pack；V2 只要求保留这些回归及隐私警告，**没有明确新 ANSM 数据进入这些路径后应如何表达**。必须在本项目统一验收以下边界：

1. **旧外部导入**：既有字段没有经核实的 CIS/CIP、包装UUID、成分强度或库存编码时，一律保持 `LEGACY/USER_ENTERED/UNKNOWN`；不能把药名文字、mg 值或用户记录推断为官方商品/精确库存；导入不自动确认实际包装，不静默新扣库存或双扣。
2. **重复导入及幂等**：重复文件、同事件 ID 不同来源、重复历史服药/修订、导入后恢复、记录撤销/恢复不能制造额外测量事件或CPA重复累计；未知原始时区/单位不默默标准化为肯定事实。
3. **导出格式**：对包含新增 ANSM 信息的既有 CSV、PDF、Visit Pack，列出完整 `EXPORT-SCHEMA-MATRIX`：实际记录时间/计量输入、包装确认状态、库存效应、来源种类（官方/自填/历史未知）、数据版本、是否已核实、缺失与冲突原因。不得把仅供内部用的整数刻度直接输出为片数、泵次或mg。
4. **冻结历史**：导出历史必须以实际记录 revision 和冻结来源为准，不随着当前商品名、目录版本或现今强度重算。不以 PK 模型研究结果替代旧导出数值。必要时仅附**解释性数据列或状态**；任何改变既有对外文件契约时提供版本/兼容策略、解析测试及前后对照。
5. **导出失败与撤销**：输出中断、超长来源/产品名、非法Unicode、未确认实际包装、零效果操作、多成分商品均要有明确语义；不能输出半份却提示完成。
6. **隐私**：保留或完善未加密 CSV/PDF/就诊包的风险提示、用户选择目标位置和操作范围；不得因为药品来源公共而误认为结合个人给药事实的导出也是公共数据。不向官方药品网站/第三方传用户记录。

如用户未要求在特定老格式中加入新字段，允许以 `LEGACY_FORMAT_UNCHANGED + ANSM_METADATA_UNSUPPORTED` 明确标记而不破坏既有接口；但**不能遗漏测试和用户可理解的限制**。单独新报告可采用新版本 schema，不得伪装成旧文件。**CSV/PDF 切换 Legacy/M1/M2 曲线属于独立 PK_DISPLAY_REVIEW，不得借本任务擅自切换。**

## 28. 生命周期与隐私：删除全部数据、回收站、清空、缓存和恢复闭环

新增官方引用、已冻结文档引用、包装/消费证明、公告来源快照与 CPA 统计后，必须证明**用户能够按原产品承诺清除自己的数据**，同时遵守只追加账本在正常业务操作时的历史保护。正常记录更正/删除是审计事件；**经确认的整库“删除全部数据”是不同的操作域**，不得错误禁止清除，也不得让它留下用户健康资料。

- 逐一盘点 Room 表、runtime epoch、辅助表、FTS/搜索索引、派生快照、Compose 缓存、持久化偏好、提醒状态、临时备份/恢复文件、系统分享目标及正常能访问的内部文件；明确各数据源的生命周期和可否由App控制。
- 原 `Delete all data`、药物物理删除、回收站/VOIDED、PRESENTATION 冻结/退休、恢复覆盖、空备份恢复及新数据集重建都必须有**不同的明确事务语义**，不能把 tombstone 当作永久清除，或把永久清除等同于消耗反向操作。
- 删除后旧 `previewEpoch` / 数据集 UUID / 待确认票据/窗口状态全部失效；原活动页面、重启后的通知、后台任务和锁定/伪装边界均不能重新显示过时个人来源、累计CPA值或包装记录。
- 与系统自动备份、用户自行外部保存的文件和其他应用接收的分享文件明确划清责任：App须可删除其控制范围内的数据，但不得虚称已经删除用户或其他应用控制的副本。`PRIVACY.md`、四语隐私声明、用户可见出口与真实实现保持一致。

## 29. 正式资料输入、更新包和外部链接的威胁模型

V2 覆盖来源许可/签名和普通坏JSON，但尚未要求围绕**攻击者操纵供应文件、更新来源、字段文本和跳转URL**建立完整的恶意输入测试：

- 输入为可疑字节：严格上限（行数、CIS/CIP长度、字段数、嵌套深度、压缩后/解压后大小、超时/内存预算）、明确编码与Unicode正规化规则；禁止通过错误正则/排序键/非法小数造成CPU或内存拒绝服务。
- 内容和编码分离：HTML/RCP/Notice 当只读文本处理，不执行嵌入脚本、HTML、可点击任意URI或伪造监管徽章；商品名称/辅料中出现 `<script>`、双向控制字符、URL或巨长文本时要安全渲染并保留可审计原文。
- 对官方网站跳转，限制 HTTPS 可信 host、精确路径/参数政策、禁止 `javascript:` / `file:` / `content:` / 非法重定向与链接注入；不要将用户 UUID、记录id、服药时间、剂量或查询文本拼入URL。外部浏览器打开会向对方暴露页面访问行为，UI需如实告知。
- Manifest SHA 只证明文件字节与记录值一致，不等于来源确为ANSM或内容真实；维护者获取时验证实际官方下载域/必要时HTTP跳转终点/源发布日期/每种资料对应的权利状态。防止镜像和伪造“官方来源”跨namespace继承认证。
- 受损/未授权数据更新不能使正式App启动崩溃、丢历史或绕过手工模式；APK 发布资源和 debug Synthetic fixtures 必须实物审查，测试输入不进入Release。
- 在 `SOURCE-THREAT-MODEL.md` 定义信任边界、攻击者能力、需要执行的负向测试和各类错误响应；不要为了方便添加 App INTERNET/外部服务权限。

## 30. 时间、时区与资料陈旧性的可验证处理

V2 明确了源更新时间与获取日期，但还缺少**手机时钟异常和离线资料过期行为**：

## 36. 不良反应报告：为用户提供官方渠道，而非自动上报

## 37. 实际计量边界补测：注射/多剂量、分片、储存和开封期限

这是对 P4/P5 和 ANSM-04 的**安全边界测试补齐**，不是自动扩大可用药品或给药途径，也不引入未经验证的 PK。

- **注射浓度/体积**：在用户手动录入的合法合成样例中，区分标签浓度 `mg/mL`、抽取体积 `mL`、瓶内名义体积、单次实际物理消耗、有效成分与盐/酯身份。只有冻结的浓度依据与产品身份适配才做有向质量—体积换算；没有时返回 UNKNOWN。不能把注射剂酯质量自动换成雌二醇游离基质量，不把入体量、残留/浪费量当作已经确认的剂量事实。
- **单次安瓿/多剂量瓶**：包装数量不等于允许复用次数；启封后残留、药液损耗、抽取死腔、废弃、复用条件均需要来源或用户单独声明。无法知道真实剩余/允许使用状态时，不凭名义包装自动放行扣减或声称可继续安全使用。不默认自动计算开启后无菌有效期。
- **片剂分割**：`0.5 tablet` 作为用户报告的物理消耗量，不等于临床上该制剂允许等分或含量均匀。可分片标志需独立官方来源核实；缺证据不写“建议掰半片”。数量换算和分片适宜性分别标状态。
- **口服/舌下/阴道/透皮等途径**：商品说明书批准途径、用户实际记录途径、PK Profile 所用模型是三种独立事实。跨途径不能因为同一个商品/CIS/成分自动把吸收率、Cmax或适用说明合并。对跨性别用途与获批适应证不同的情况只如实展示商品信息，不给用户适应证资格判断。
- **效期/开封后期限与批号**：未开封标示有效期、开封后可用期限、用户录入开封时间、批次/召回匹配是不同字段；来源未知时不得生成“还能安全用 X 天”的断言。库存数量可计算不代表产品在医学上仍可用。批号缺失不能宣称该用户包装已被召回；允许记录未知及只读人工核对建议。
- **库存处理与实际服药是不同事件**：过期、泄漏、丢失、遗弃、开封损耗等如果被实现为库存事实调整，必须具有明确用户确认、原因、时间、可追溯操作 UUID，不得虚构服药记录、累计CPA给药或PK效应；已有 VOIDED/ADJUST/REVERSE 合同不能被绕过。

测试至少涵盖：注射浓度错单位、同名不同酯、手动缺来源、单次安瓿错当多剂量、消耗后调整、部分浪费不计入实际服药、半片未知分割资格、批号为空、资料效期与库存预测冲突、包内名义数与实数不一致、不同给药途径引用历史冻结。生产支持范围不包含的药物形式明确标 `UNSUPPORTED_SAFE_FALLBACK`，不得为了“全做完”临时发明转换。

## 38. 外部浏览器、身份与网络边界的技术性更正

V3 的任何“阻止 HTTP 跳转至异域名”的说法必须按真实控制范围解释：**App 可以拒绝发出不可信 URL，但不能控制用户在独立浏览器打开官方页面后，该页面自己的服务端重定向或浏览器操作。** 因而不能用“浏览器最终落点均在白名单”作为对外安全保证。

可测试且必须做的事项：

1. 发出 Intent 前，仅接受严格解析的 `https` URL，经过 IDNA/大小写/端口/用户信息/百分号编码/Unicode 主机名归一化；逐项核查可信主机、期望路径/查询键、产品 CIS/CIP 一致性。对于任何混淆、不认识的子域名、IP地址、`file/content/javascript` 等方案都明确拒绝。
2. 优先构造已核实的**固定公共产品/文档页面**路径，不能把用户原始文本直接接成 URL；不得附加用户 UUID、私人备注、剂量、就诊日期或跟踪标识。URI 可携公共官方产品标识，但不能携个人健康事实。
3. 只有解锁后的真实用户动作才发起外部 Intent；目标 Activity 不存在时给出可回退状态；隐私说明准确提到点击后浏览器与网站可以获取所访问网页的信息。不嵌入有权限的 WebView，不因功能需求添加 `INTERNET`。
4. 如需验证最终跳转/页面内容，只能作为**独立维护者审查流程**，不把浏览器外部行为写成 App 可强制保证，也不得在离线端偷偷发起请求来“复查”。
5. 测试安全主机前缀诱骗、Unicode域名、端口、userinfo、相似域名、双编码、任意查询参数、`intent:` URI、Activity 异常、AppLock/伪装、无浏览器及无用户手势。

## 39. 最终临床内容、来源与发布开关的“三向一致”闸门

ANSM-04/05/06 不能只验证资源 JSON 解析、界面出现和四语 key 齐全。建立每条**正式用户可见的医疗/监管信息**的三向可核查关系：

- **来源**：产品/成分/剂型/途径/适用人群、官方文件和节、原始法文/结构化字段、法律再利用状态、资料有效时点、内容核实日期、审阅人/审阅过程及审核状态；未审查即 `CONTENT_UNVERIFIED`。
- **陈述**：UI四语文案/字段，谁做的翻译和审核，是否忠实于来源、是否跨适应证/地区泛化，是否将统计相关说成个体建议；不同国家/产品和官方原文的冲突如何作为 UNKNOWN 公开。
- **发布控制**：本构建实际打包哪个数据版本、Release 中有哪些资源、哪些患者可见路径被启用，是否在许可或校验失败时保守关闭；关闭后不能留下缓存、截图、搜索建议或无来源“风险值”。打开开关须有可审核的每条声明级证据，不能凭整个目录的 SHA 就默认所有句子可靠。

同时建立 `PRODUCT-CONTRAINDICATION-AND-MONITORING-COVERAGE.md` 或纳入既有 `SAFETY-COVERAGE.md`，映射 ANSM-04/05 的每一条敏感声明（尤其 CPA、螺内酯、凝胶接触转移、贴片、黄体酮过敏与相互作用）、四语审查状态、来源链接和应用页面。无法完成逐条医学核实的项目只读链接/UNKNOWN，不做自动提醒或治疗建议。

构建期与端到端验收：同源不同版本冲突、法语原文变更中文未更新、四语中任一误写反义、来源被撤销、许可 OFF、快照校验错误、导入外部恶意说明文字、锁定模式缓存暴露等，必须使受影响的展示进入 `BLOCKED/UNVERIFIED` 而不是保留曾经的绿色成功标识。工程上的校验只是持续检测工具，不替代具资格的医学、翻译或法律审阅。
