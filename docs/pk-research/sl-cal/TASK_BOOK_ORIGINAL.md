## 2. 研究内容

### A. 问题定义

- **校准对象**：E2 合计 = 舌下部分（M2 形状）+ 非舌下部分（现有兼容模型）+ 背景基线（只计一次）。
- **观测**：用户的化验总 E2，带采样时间。写清楚以下两点对拟合的影响：
  - 检测方法差异：免疫法与 LC-MS/MS；
  - 单位换算。

### B. 候选方案（至少比较以下四种，可以补充）

1. **只校准舌下幅度**：对 M2 的幅度 A 乘一个个人系数，形状不变；非舌下部分沿用现有 P1 校准或不校准。
2. **两个系数**：舌下系数 + 非舌下系数，对合计联合拟合。必须分析可辨识性：化验少、两途径同时存在时，两个系数能否分开？分不开时如何收缩到先验或合并为一个？
3. **一个共同系数**：合计整体乘一个系数。最简单，但会把两种途径的个体差异混在一起。写明适用和不适用的场景。
4. **复用 P1-A 的拟合框架**：把旧舌下模型的形状换成 M2 形状。评估能复用多少代码和结论，以及参数语义是否兼容（参照 `p2/model-selection.md` 第 3 条）。

对每种方案说明：参数、先验与边界（安全上限）、拟合方法、需要的最少化验数、不确定性怎么表达、计算成本。

### C. 资格条件（化验能不能参与校准）

在 `CalibrationEligibility` 现有规则的基础上，针对舌下补充以下条件并说明理由：

- **采样时间必须已知**，并能算出距上次舌下服药多少小时。舌下峰值在 1–2 小时内，采样时点相差 30 分钟，读数就可能差好几倍。
- **采样时点在峰值附近时的处理**：降低权重，还是排除？比较两种做法。
- **前 N 小时内的服药记录必须完整**：沿用 P1-B 的历史完整性门控。
- **化验数量不足时拒绝校准**，并给出可以直接显示给用户的原因文字。

### D. 验证

1. **合成数据**：
   - 已知真值的虚拟用户若干，覆盖以下维度：只有舌下 / 混合、化验 1/2/3/5 次、采样时点（谷值、峰值附近、随机）、个体幅度差异（如 0.3×–3×）、检测噪声；
   - 对每种方案报告：系数恢复误差、留一化验预测误差、校准后曲线与真值的差距；
   - 不需要外部数据。
2. **已发表数据的条件性检查**：只用仓库已有证据目录中允许使用的统计摘要，不复制原文、图表或个体数据。作为外部诊断比较，不称为“验证通过”。
3. **负责人自己的化验（可选）**：
   - 如果负责人愿意，提供一个**只在本地运行、不读写仓库数据**的验证流程说明，由负责人决定是否运行；
   - 真实健康数据**一律不得进入仓库、提交、报告或日志**，报告中只记录“是否运行”和汇总结论。
