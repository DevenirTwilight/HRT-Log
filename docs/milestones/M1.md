# M1：实现与验证

基线为 `bd2a6bd` 的 `docs/PLAN.md`；本次没有修改 PLAN，也没有新增 PK/导入算法、M2 库存 UI 或伪装功能。

## 实际实现

- 工程模块：app、core/domain、core/data、core/reminder、core/ui、pk-engine、importer。
- 固定工具链：JDK 21、Gradle 9.3.1、AGP 9.1.1、Kotlin/Compose 编译器 2.2.20、KSP 2.2.20-2.0.4；Compose BOM 2025.10.00、Room 2.8.3、SQLCipher Android 4.10.0、Hilt 2.57.2。compile/target SDK 37，平台 37.0，build-tools 37.0.0，minSdk 26。
- full / play 两个变体，均为 `net.plainnotes.app`。release 开启 R8，尚未配置发布签名。
- JVM 领域层：每 N 天、每 N 真实小时、每 N 周的星期集合、多个墙钟时刻；纯函数展开，不持久化大量 PENDING。春季间隙推至第一个有效时刻，重复时段只取较早偏移。
- 身份：`wall:<version>@<原本地时间>` 或 `elapsed:<version>#<occurrenceIndex>`；改期不改身份。UTC 半开版本区间，即时切换时保留必要的旧槽位快照。
- 同药下一计划边界固化 MISSED；没有下一槽位则保持迟服。已发生记录使用存储的 UTC/时区/剂量/迟服参数快照，补记更新原 MISSED。
- 单次覆盖支持改期、改剂量、跳过组合、部分撤销和恢复默认后的删除；真实已服记录不能被覆盖操作删除。
- Room v1 全部规划表，加上必要的 retained_slot 和 reminder_mapping（都在主库）。导出 `core/data/schemas/net.plainnotes.app.data.NotesDatabase/1.json`。状态/NULL、外键、区间重叠、有效剂量和覆盖组合由 SQLite 触发器兜底。
- 库存追加流水 schema：跨容器消费、冲销关联、幂等键及用量缓存触发器。M1 实际服药保留待分配库存数量，M2 再接库存操作和 UI。
- 随机 32 字节 SQLCipher 口令，Android Keystore AES-GCM 包装后用 AtomicFile 存储于 noBackupFilesDir；不使用 PIN，不保存裸密钥；未首次系统解锁拒绝打开主库。已有库但密钥缺失/解密失败时保持原文件并报恢复错误。
- WorkManager 使用 Configuration.Provider 按需初始化，移除默认初始化器，只在首次系统解锁后使用，避免 Direct Boot 初始化凭据数据库。依据：[官方按需初始化文档](https://developer.android.com/develop/background-work/background-tasks/persistent/configuration/custom-configuration)。
- AlarmManager：检查精确闹钟权限；普通 exact/idle、拒权后的不精确降级、高可靠 setAlarmClock；高可靠默认关闭。接收开机、锁定启动、解锁、时间、时区、包替换和获权事件，应用启动/数据变更及每 6 小时尽力维护时重排。
- Direct Boot 48h 原子缓存只含 opaque ID、触发时间、模式、缓存代次/消费状态，不含 slot_key 或健康信息。消费前落盘以拒绝重复派发，同刻提醒批量消费；映射在 SQLCipher 主库。改期/取消先使缓存失效，解锁后 reconciliation。
- 中性通知、点击打开完成页、已服按计划剂量和当前时间幂等记录、稍后 10 分钟（重排保留，改期/取消失效）；未解锁时不提供写主库的服药操作。提醒触发本身从不代表已服。
- Compose UI：药物新增/编辑/停用归档，雌二醇途径/酯型，规则设置；日历按日期显示状态、实际时间/剂量完成、过去日期补记、单次覆盖、计划外服药、预约；权限、通知渠道、电池状态/厂商设置引导及一分钟测试提醒。各页面提供 Preview，真实窗口设置 FLAG_SECURE。

## schema 实现细节

Room 的 `@Index` 不提供部分索引谓词；`SchemaGuards` 使用同名同列索引将有效记录槽位唯一约束落实为 `WHERE deleted_at_utc IS NULL`。JSON 保留 Room 生成的索引描述；运行时触发器和部分谓词以 `SchemaGuards.kt` 为准。重建/迁移须安装同一组约束，MigrationBaselineTest 是 v1 起点，后续每次升级必须补 Migration 和验证。

这是实现适配，没有改变 PLAN 的部分唯一约束设计。历史配置额外存入不可变规则和服药 JSON 快照，字段不是 PK 默认值。

## 自动验证

本地自动测试 **47 项通过，0 失败**（领域 25、Room/密钥边界 12、提醒 10；另新增首次解锁前通知完成保护测试，待本轮重跑）。两个 Debug APK 及 instrumentation 测试 APK 构建成功，两个 Release 曾完整构建成功；最新源文件的 Release 及 CI 结论在最终交付更新。本地无 `/dev/kvm`，软件模拟器超过 16 分钟仍未完成启动，未运行原生测试；CI 已配置加速模拟器运行此层。测试分层：

- JVM：规则、DST、时区、版本切换、组合覆盖/撤销、下一槽位漏服、长周期、补记、导入统计起点、历史时间快照、缓存消费模型。
- Robolectric：真实 Room DAO/SQLite 触发器及事务回滚，锁定状态拒绝主库、丢失密钥不覆盖文件；DPS codec 字段白名单；锁定启动调度、旧代次拒绝、取消/改期旧请求拒绝、批量消费与重复派发；API 31 精确闹钟拒权降级、高可靠系统闹钟及撤权检测。
- Android instrumentation：v1 schema 起点；真实 Keystore + SQLCipher 加密、重新打开、缺密钥不覆盖，以及通知源改期失效/完成幂等。模拟测试不能替代这一层。
- 构建：两个变体的 Debug/Release，instrumentation 测试 APK；release 合并后 manifest 检查 INTERNET 和 applicationId。
- GitHub Actions：独立 JVM、Android 构建/单测及 API 35 模拟器原生集成测试 job，固定 actions commit，检查 schema 导出一致性及上传 APK/测试报告。

## 真机逐步验证（仅用合成内容）

1. 安装 fullDebug 或 playDebug。首次启动不要求体重，添加测试药物并设置剂量/容量、提醒和迟服分钟数；关闭再打开，应保留数据且不出现错误。修改名称/途径后过去服药配置快照保持原值。
2. 建立早晚两个时刻、每 N 天、每 12 小时、每 N 周多个星期，检查计划。选择过去日期补记，修改实际时间和剂量；重复提交同槽位不得产生重复记录。
3. 对同一槽位同时改期、改剂量、跳过，逐项撤销，再恢复全部默认。确认原槽位恢复且无重复行；已完成槽位无法用跳过删除真实记录。
4. 检查迟服边界前/正好/后。等待同药下一槽位到来才判 MISSED；另一药的下一次不影响它。用每 7 天测试规则确认没有固定一天判漏服；停止规则而无后继时不自动判漏服。
5. 当天 15:00 修改早晚规则，上午历史不变，切换时刻不重复；将旧槽位改期到新版本后，再修改版本，该次改期仍保留。更换时区，已发生记录 UTC/时区不变，未来墙钟时间随当地，小时规则间隔恒定。
6. Android 12+ 拒绝精确闹钟权限，日历显示延迟提示且使用降级；授予后重新排精确提醒。撤销时系统可能停止应用并取消闹钟，重新打开后应检测并降级；不要把这段中断误认为无风险。
7. Android 13+ 拒绝/授予通知权限，关闭/打开提醒渠道，可靠性页应反映状态。允许后发一分钟测试提醒，通知只含中性文字；打开、稍后十分钟、已服操作分别验证；已服重复点击只产生一条实际记录，已改期/跳过后旧通知操作不得写入。
8. 关闭屏幕、进入 Doze，比较普通模式与高可靠模式；高可靠模式会显示系统闹钟信息。小米/华为/三星分别按系统设置允许后台运行，并独立测试；不能据模拟器结果声称 OEM 可靠性通过。
9. 正常重启后解锁，检查未来提醒重建；再重启，首次解锁前等待已缓存提醒，中性通知应可触发且不能写主库。首次解锁后不重复提醒。
10. 对未来提醒改期或取消，立即重启，旧时刻不应再次响。分别在缓存更新中途终止进程、缓存损坏和数据库与缓存不一致时验证：旧代次不重响，解锁后主库恢复未来安排。
11. 检查超过 48h 不首次解锁的缓存耗尽边界；未解锁更换时区保持缓存 UTC，解锁后更新墙钟时间。正常使用滚动维护应覆盖后续 48h。
12. 强制停止应用、拒绝后台权限、关机分别检查已说明的限制，恢复后启动应用重排。开启/关闭高可靠模式并验证缓存模式更新和重复事件去重。
13. 添加预约，检查提醒提前量与重启恢复；计划外服药只记实际发生，不冲抵任意计划槽位。
14. 运行 `./gradlew :core:data:connectedDebugAndroidTest`，确认真实加密与重新打开通过。实际 app 数据文件不得显示 SQLite 明文头，包装文件不含裸口令；丢失/损坏包装密钥应报恢复错误而不创建空库替换。

## 当前限制

- 尚未得到真机/OEM/长时间未解锁/真实 Doze 验证结论；软件模拟器也不能证明这些场景可靠。
- Force stop、关机、撤权到应用恢复的间隔、缓存窗口耗尽均可能中断提醒；未解锁换时区无法仅靠最小缓存重算墙钟规则。
- 缓存消费先持久化再发送通知：崩溃在二者之间可能漏一次通知，以避免不确定状态重发。通知被拒绝时不能显示；应用中仍可查看槽位。
- 后台 Receiver 工作受系统时间限制；大量多年历史补账可能需要后续优化/真机压力测试。WorkManager 看门狗不保证准点。
- M1 的库存仅有 schema 与待分配数量；完整扣减、库存修正及编辑/删除联动在 M2。药物删除表现为停用归档，保留引用和历史。
- 当前 UI 是英文资源，三语及应用锁/隐蔽文字自定义在 M6；伪装在 M7。现阶段通知统一中性，真实界面 FLAG_SECURE 已启用。
- PK、化验 UI、导入、备份/恢复和导出尚不属于 M1；密钥损坏不会覆盖原数据，自动恢复流程在 M5。
