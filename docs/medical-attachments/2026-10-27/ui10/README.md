## 2. 新界面（生产，后端已具备）

- **医疗档案**（`MedicalRecordsScreen`）：`PrimaryTabRow`（医疗记录 / 医疗文件）。文件能力未接入时不出现标签页，页面与原先一样只有记录。所在区域在打开记录页再返回后保留（AppShell 的 `rememberSaveable`）。
- **化验结果页**（`LabDetailPage` / `LabDetailFullscreen`）：自己的窗口，系统返回直接关闭；LABS 列表和就诊页里的化验行都直接打开它，不再有「列表弹窗 → 附件页弹窗」两层。只有真正输入过的字段才显示；全部为空时一句话说明如何补充。不做任何“偏高/偏低/正常”判断。大字号或窄屏时「编辑」只留铅笔图标并读出名称，标题不换行。
- **相关文件**（`MedicalAttachmentsSection`）：见差异矩阵。保留全部既有安全行为：只有真实 COMMIT 才显示「已保存」；取消后无挂起操作；不确定只给只读「检查状态」，不再写；锁定、伪装、切库先清空再回收像素。
- **文件页**（`MedicalAttachmentViewer`）：采用样图 07 的版式；PDF 仍只有第一页（Android 9 及以上），Android 8 可保存与备份、不提供内置预览，没有声称多页阅读器。
- **选择记录**（`AddFileTargetDialog`）：就诊 / 化验结果两段，列表按时间倒序，没有预选；化验结果打开的是单项，不是批次。

## 3. 仅组件 + 合同（等 MED-03，不接生产导航）

`attachments/ui/library/`：`MedicalFileLibraryScreen`（样图 06：搜索、添加、待整理、分类、最近文件、完整备份）、`MedicalFileDetailPage`（样图 07：关联记录及范围、只显示已知字段、回收提示）、`AddDocumentDetails`（文件优先导入第二步：标题、类别、四种关联方式）、`RecordFileOutcomeCard`（记录优先：记录与文件是两个事实）、`MedicalAttachmentsSection(onChooseExisting)`。所有能力开关默认 false，禁用控件写明原因。接口合同见 `INTERFACE_CONTRACT.md`。
`MedicalAttachmentUiGuardTest` 新增：任何生产文件都不得引用这些组件；它们不含存储、密钥、路径或运行时调用。

## 4. 化验批次

当前 MED-02 目标只有单项 `LabValue.id`。合同里 `RecordTarget` 把 `LabPanel` 与 `LabValue` 分成两种目标，`DocumentLink` 在页面上显示「整份报告 / 单项结果」。UI-10 没有把 panel ID 传给只支持 LAB 的接口，也不按日期推断关联。批次关联由 MED-03 实现和验收。
