| Boundary | Actual behavior and remaining obligation |

The small production fix invokes the SAME guard in the first actual `AttachmentTransaction` before bind/read. The store guard remains an independent PREPARE recheck. A **genuinely empty fallback** (no business, attachment or unknown resources) is not inherently a protocol blocker. It has not been shown to satisfy atomic joint admission and end-to-end post-restore writing in this slice. No blanket assertion that *all* restored libraries require a new format is made. No unsafe fast path, trust cache or second validator is added.

Native test extends the existing real-generation case: create a previously unbound typed target, use a genuinely failing provider, then require the joint-admission error **before any provider open**, unchanged business bytes, legacy bytes, complete attachment-table value digests, object-byte hashes and aliases, and NOT_FOUND for the attempted operation. Existing stale-reader and refused-export assertions remain. This test is source-derived RED on the old order; it has not been executed on the old SHA, so no native RED is claimed.

## Concrete minimum multi-library compatibility proposal — NOT APPROVED / NOT IMPLEMENTED

This is the necessary format decision for the normal **nonempty retained-library** case, not permission to enable the feature or permanently freeze a protocol.

1. Use a distinct **PNMEDBK2** discriminator/version. Keep PNMEDBK1 and PNBAK1 readers, writers and cryptographic meanings unchanged; old readers reject the new header before KDF/allocation. Do not smuggle a collection into a v1 manifest or concatenate v1 files and call them complete.
2. One authenticated collection index declares `collectionUuid`, `activeLibraryUuid` and an exact sorted set of libraries. Each entry binds stable `libraryUuid`, role ACTIVE/RETAINED, original dataset/epoch/logicalVault, business-byte length/hash, manifest-byte length/hash, and its exact version/object membership and ciphertext lengths/hashes. Each library reuses existing complete business/attachment validation. IDs are scoped by `(libraryUuid, typedRecordUuid)`; integer IDs are never cross-library identity. Empty retained libraries are explicit members, not guessed absent.
3. One authenticated outer stream binds header, index, every library's business/manifest bytes and exact ordered members; reject missing/extra/duplicate/out-of-order/trailing members. Reuse Argon2id 65536KiB/3/1, Tink64KiB, and AES-GCM portable DEK wrapping. New outer/wrapping AAD and HKDF labels must be v2 domain-separated and include collection/library/version identity. This changes ONLY a separately approved new protocol, never v1 ciphertext or derivation. No custom primitive.
4. Keep existing global caps **across the entire collection**, not per library: business JSON aggregate ≤32MiB, rows ≤100000, manifest aggregate ≤8MiB, versions ≤1000, archive wire ≤1GiB / ciphertext ≤512MiB. Local joint ciphertext ≤256MiB and alias ≤512 still apply to old + staged new resources. Restore may honestly REFUSE an otherwise valid archive that cannot fit locally; no truncation/history loss. The proposed library-count cap is **8** (ACTIVE + at most 7 RETAINED); all aggregate caps apply even when each member would pass individually. More retained libraries cause explicit refusal, never omission.
5. Reader authenticates the entire declared set before activation. Reuse current independent business preflight, Tink member authentication, fresh target keys and held namespaces. Assign fresh per-library local identities with exhaustive typed mappings; never clone source aliases. Stage all members while retaining the old set, verify independently, then one root-authority transaction declares the new ACTIVE member and all its retained members. Unknown ownership or unresolved materialization refuses restore/export/write. No second restore engine or multiple rename pseudo-commit.
6. Joint import admission must be rooted in the same authority transaction that commits a durable new-operation reservation. Count reservations/actual objects/keys for **all** libraries, not only original restore plans. Bind admission to operation UUID + request digest + scope; final COMMIT rechecks scope/reservation. No across-transaction trust token. Interrupted/unknown resources remain charged. Do not implement this until the collection can be completely exported and budgeted.

**Approval sought next:** authorize a default-OFF PNMEDBK2 collection implementation under the above compatibility constraints, followed by exact byte-layout review before protocol freeze. It does not authorize higher quotas, permanent deletion, real originals, release signing or public enablement. Until approved and verified, existing restored writes and nonempty-fallback export remain refused.
