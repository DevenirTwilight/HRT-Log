# Next integration boundary (not implemented)

Owner-approved OFF PNMEDBK2 codec is PR121; this note is the minimum compatibility/work-ownership decision for the remaining actual operation chain, not another validation engine. Default main after PR120 is efb2ff5d / Room16 / records Schema13. Do not reserve a migration version until checking then-current main/active PRs.

## Why merely removing the guard is unsafe

1. `LibraryRestoreAdmission.inspect` knows original candidate alias plans/reserved ciphertext, real files and actual aliases. A new operation PREPARE in a managed child introduces **new unmaterialized alias and byte reservations** that the old algorithm does not read. An older Room16 client can therefore admit another restore between child PREPARE and key creation using an incomplete budget. Actual alias enumeration cannot count keys that do not exist yet. Root-gate serialization alone does not fix an unaware older writer after that gate is released.
2. `library_candidate` persists one operation→one generation. A complete collection needs durable exact membership, active-member selection, source→fresh local mappings, resource ownership and one whole-request receipt across up to eight candidates. UUID/hash matching alone is not a substitute for a persisted declaration after restart.
3. The root singleton remains the sole visibility authority. READY flags, file renames, a group receipt or child DB commits must not independently select a dataset.

A next-version Room fence is consequently justified **if managed-child writes are introduced**: old clients must reject the new local protocol rather than run unaware admission. It is not needed by codec-only PR121 and is not implemented here. Proposed minimum local tables are an immutable collection-restore request and typed source-library→candidate membership; group phase is historical receipt evidence, not a second active pointer. Do not hide group data in unrelated business text or reinterpret a digest as full membership. Migration adds control evidence only, preserves every old candidate/owner and unknown resource, infers no old groups, and keeps ordinary business Schema13/PNBAK1 unchanged. Exercise all existing1..16 upgrade paths and downgrade refusal; no destructive fallback.

## One next integration PR, real dependencies

- Reuse `AttachmentBackupPreparation` rules via a small connection/authority adapter, not a second validator. Acquire bounded read-only retained SQLCipher handles through existing held generation contexts and existing key envelopes, no key creation or .bak adoption. Data scope of a retained library differs from the **single current authorized backup owner**; freeze both explicitly. All snapshots in the set must follow the same current owner's revocation/generation/epoch guard. Do not fabricate separate independent UI permissions for retained libraries.
- Root legacy and all ACTIVE/RETIRED candidates, including genuinely empty retained libraries, must be represented. Preserve historical UNKNOWN and all unresolved owners. Unavailable keys, missing objects, unsupported retired logical namespaces or unfinished resources refuse a complete claim. Compare exact full snapshot membership with fresh persisted inventory before and after export. A count is not full authentication or a transferable write permit.
- Native SQLCipher read-only snapshot transactions must be real; do not override `inTransaction()` to make an oracle run. Use supported public APIs only. Read-only connection and held namespace/key lifetimes must outlive snapshots and be revoked/closed without deleting source files/keys.
- Prepare a complete collection and all per-member candidate/owner rows in one root transaction, reserve the aggregate old+new budget, then irreversibly start all materialization owners before any file/key primitive. Reuse existing independent preflight, business reconstruction and object installation per library. Persist/reopen/authenticate every member before one root transaction switches the authority and records the group receipt. Any pre-switch failure leaves the previous dataset active; no automatic permanent cleanup.
- Joint import reservation must be committed in the actual child transaction while the root authority gate is held. The gate is exclusion, not a second write/commit point. Charge all libraries' planned and actual aliases, unfinished journal reservations, committed/history/trash/quarantine bytes and database/WAL/free-space allowances, without double-charging the same physical bytes or crediting unknown resources. Reuse held-directory leases safely; never reopen a lock FD that could release an existing POSIX lock.
- Only after exact complete-backup eligibility and projected row/manifest/version/space bounds are proven may typed binding and PREPARE occur. Do not bind a new record or read a provider merely to reach a known refusal. Same UUID/different payload refuses; uncertain commit is read-only reconciliation. Preserve source records/units/PK and all existing app request-scope checks. Do not expose Room, paths or keys to Compose.

## Finite acceptance

Synthetic two-generation case: old root retains PDF/PNG/binary/history/trash → restore/activate a new library → full set capture → atomic joint admission → new attachment → reopen → PNMEDBK2 export → independent reader → new-device persistent complete-group restore → one authority switch → fresh process → per-field/hash/typed-link comparison. Both same-integer-ID and duplicated portable content IDs stay explicitly scoped; never deduplicate required retained libraries to pass quotas.

Negative cases: wrong password/missing/extra/corrupt members; unknown ownership/missing aliases; insufficient aggregate resources; stale scope/ABA/UUID conflict; cancellation and death at prepare/materialize/commit/switch. Reuse existing native API26/29/35 and fixed low-memory/restart gates. Keep old failures. Public imports/view/restore, physical deletion, real originals, permanent format freeze and signing/release remain OFF. External review is not performed by this work.
