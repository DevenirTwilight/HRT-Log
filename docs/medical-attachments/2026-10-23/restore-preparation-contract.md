# Restore preparation, default OFF

Baseline `4dca6744e93ad585a2a824262bd72d083e4f2bce` (#111 merged). Authorization §147.A.

`AttachmentRestorePreflight.inspect` is production admission independent of a wire format. It consumes/wipes strict bounded structured JSON using the existing indexed parser/version gates, checks exact known table names, typed source/trash target presence, reference-vs-snapshot trash semantics, complete object index, contiguous immutable version ordinals, latest pointer, typed destination row mapping and tombstones. Caller lists are frozen. Missing/unknown/extra/duplicate identities or failed evidence refuse the entire preparation. This is closure checking, **not authentication**: a future independent approved reader must bind the authenticated manifest, record bytes and full member set. It does not prove arbitrary imported business facts satisfy the full database oracle; that remains mandatory before future activation.

`AttachmentRestoreStaging.stage` copies only existing inner Tink ciphertext into `noBackupFilesDir/attachment-restore-quarantine-v1`. It reuses the exact held-FD ownership/exclusive-create/fsync/seal mechanism and process/kernel writer exclusion, with a fixed namespace enum rather than caller paths. Fresh physical UUIDs never replace clinical objects. Every member gets full existing cipher hash/length and plaintext AEAD/hash/EOF authentication with a borrowed portable DEK; DEKs are consumed/wiped, never wrapped or persisted. Input is bounded, cancelable and private; no plaintext file or DB write. Live committed destination scope is checked before/after slow work, with no slow IO under the COMMIT/revocation monitor. Current user DB, pointers, journal, namespaces and keys remain intact.

The returned receipt is explicitly **inner objects verified only**, `wholeArchiveAuthenticated=false`, `activatable=false`. It has no activation API. It cannot authorize a subsequent SQL commit. A future format adapter must independently verify outer authenticated EOF, all metadata and final set before a separately approved durable restore coordinator may act. No production archive writer/reader/password parser/KDF/envelope is implemented here, and the test-only candidate is unchanged.

## Resource and recovery boundaries

Preflight budgets every retained ciphertext rounded to allocation units, bounded rows/objects/entries and known retained staging occupancy; two new aliases/one-use invocations per retained version are conservative **planning**, not durable reservations. Staging itself performs no encryption/wrap or alias generation. Before future key use the approved coordinator must durably reserve actual invocations, without refunds. Staging rechecks actual bounded inventory/allocated blocks/free bytes before source open and after each complete object. Unknown regular leaves are charged; symlinks, unowned leaves, overflow and insufficient space refuse. Engineering defaults are internal OFF budgets, not a new approved format limit. Free-space checks do not promise future IO success or reserve storage against other apps.

Headroom covers ciphertext preparation plus record bytes and an explicit safety floor. It is **not** proof of total restore space: isolated SQLCipher business staging, index/WAL/activation rollback, pinned old library, portable wire input and KDF working memory must be budgeted by the future complete coordinator. There is no claim of low-memory full restore acceptance.

No Room migration or durable restore journal is introduced. Every attempt is fresh and nonresumable; repeat calls can create more charged quarantine objects and are not idempotent restore commits. Cancel/failure/process death leaves only ciphertext. New process has no capability/receipt/proof: inventory reports all leaves as unknown and never opens/adopts/deletes/auto-activates them. Unknown retained data can exhaust the bounded budget; explicit permanent cleanup remains unapproved. Future durable journal/idempotent activation requires separate reviewed generation/transaction semantics; existing object journal is not repurposed as whole-library proof.

The current snapshot refuses retained typed records/documents/links as well as versions in other namespaces. It refuses incomplete/quarantined journals and unknown/unrepresented leaves in the original object directory: exact owned inventory must match all required originals. Verifying only known versions is insufficient to call a source complete. Such sources are **not fully backed up**; supporting retained orphan namespaces/attempts with honest absent clinical targets remains a distinct model/approval obligation. No file/key is deleted to make export pass. Separate restore quarantine is excluded from the live library, has no committed clinical identity and is never exposed as a restored library. PNBAK1 ordinary backups and Room14 are unchanged.

## Existing correctness issue found while composing the production paths

Clinical dose-record trash is reference trash: the soft-deleted `dose_record` remains in its table and `trash_item.payload_json` may be `{}`. #111 snapshot assumed every typed trash row lived in payload tables, so a valid dose attachment could not be backed up. The snapshot now checks committed payload digest, exact RECORD ref and retained soft-deleted row; LAB/APPOINTMENT still require exact snapshot membership. This fixes refusal of valid data without weakening missing-object/evidence checks or changing clinical data. Original complete authentication and audits remain.
