# 统一预测及提醒不确定性合同（提案）

状态 DESIGN；B0只读DTO验证为TEST_ONLY。生产StockForecast/StockAlerts不变。

未来同一个结果供日历、库存页和提醒消费，至少包含：

- 各已确认兼容库存组及准确可用量；不能跨成分、规格、给药单位合计。
- 身份/单位/容量未知的容器及原因，不能视为零，也不算“库存充足”。
- 已记录但未分配的实际量，带原始量纲和来源；不同量纲单列。
- 计划用量证据、预测窗口和来源快照版本、算法版本。
- 完整性、第一不覆盖时间/已覆盖到何时，或不可预测原因。

混合规格即便都“片”也不能给总片数。未知库存可展示已确认子集，但不能用该下界给确定的“可用X天”。
计划来自mg而没有已确认每次实际来源，也不能拿总mg自动分配。不能把未来计划当实际包装确认。
仅当全部输入可证明兼容、历史未分配量已明确处理、计划覆盖条件满足时，才有资格计算日期；不是一切UNKNOWN都自动发“缺货”。
本轮ShadowForecastContract即使completeInputs=true也不计算日期（NOT_IMPLEMENTED），不冒充生产预测器。

保留既有窗口366日、低库存从今日至第6日（7日）及当地日历日期差；不用固定24h取整跨DST。
提醒权限、药物通知开关、review状态、每日去重与开封有效期独立，不能以静音改变页面库存判断。
旧untracked和未来unknown不是等价：旧页面现状只作基线，未来需经批准独立显示“计量资料未知/需人工核对”。
覆盖当前巴黎春秋DST两端第6/7日边界，实际调用StockForecasts与StockAlerts共用结果；不发送通知。
本轮无正式UI/文案/提醒行为修改，真机和新未知UI验收NOT_RUN/NOT_IMPLEMENTED。
