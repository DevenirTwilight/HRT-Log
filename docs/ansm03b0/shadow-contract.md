# B0 只读影子合同 v1

不替代SupplyLedger，不在用户设备后台运行。输入只有合成不可变数据；不能接DAO/Repository/Context或回调写接口。
每条请求绑定dataset/medication稳定身份、recordUUID+revision、业务opUUID、明确实际量及其语义、实际容器选择及冻结ref。
容器有独立stableUUID/旧整数handle/状态/顺序/单位/已确认可用量/已用量与冻结来源；旧未知字段不能由当前名称/规格补齐。
只在明确确认的、同一冻结商品规格/包装/版本与兼容单位的容器池内模拟旧FIFO。混合规格拒绝自动拼凑；需用户明确每份来源，另审UI。

输出分别记录：CONVERTIBLE / UNKNOWN / REJECTED / REPLAY；准确库存量、预期分配/未分配量、未知/差异原因、额外确认需求，及对旧观察值的比较。
旧观察Double以实际二进制数值比较，使用明示旧EPS=1e-9，仅称APPROXIMATE_MATCH；原始历史精度始终UNKNOWN。
不能把Double.toString/BigDecimal.valueOf等当恢复原始精确量。单位不明不比较，不把未知当0或库存足够。
已知单位相同的实际计数可直接按单位规范化；跨量纲必须复用03A有向、经确认且匹配冻结ref的关系，不自动取倒数。
包装名义64泵与实际确认容量独立，剩余克数不能推出可用泵数，释放速率/吸收质量不能作库存用量。

同业务UUID需以数据集域隔离；重放必须匹配完整输入/记录修订/容器选择/来源版本。冲销使用原捕获数量与容器，不重新转换。
贴片APPLY是使用事实；REMOVE/DETACH不创造新消耗，REPLACE须新明确贴用事实；同事件UUID重复不得产生新分配。
观察到重复/错序/错容器/错revision/错误逆量/不兼容单位必须报告差异，不能只比较总数。
未知和失败仅返回报告；不能调用既有库存写入、更正、提醒或后台任务。

预测合同只作测试：已确认兼容库存可给下界，未知库存/未分配实际量单列；无法证明完整性时不给确定用尽日期或“充足”结论。
日历/库存/提醒未来应消费同一个结果；本轮不改生产StockForecast/StockAlerts。
